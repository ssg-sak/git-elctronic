# D1 최신화 — 쉬운 설명

| | |
|---|---|
| **누구용** | ① 본인 · ②가 “이 파일 뭐야?” 물을 때 |
| **한 줄** | **충전소마다 한 줄짜리 표(D1)** 를 최신 info·상태·이용강도로 다시 만들고, **공용만 센 숫자**를 KPI에 찍는다 |
| **점수** | 안 만듦 → ② |

---

## 비유

식당 추천 앱이라고 치면:

| 말 | 실제 |
|---|---|
| **info** | 가게 명부 (어디 있는지, 몇 석, 회원제인지) |
| **status 스냅** | “지금 빈자리 있나” 실시간 메모 |
| **usage_level** | 예전에 손님이 많았는지 (적음/보통/많음) — **지금 비었나를 바꾸지 않음** |
| **D1** | 가게마다 **한 장 요약카드** (②가 점수 낼 때 읽는 입력) |
| **공용 후보** | 아무나 갈 수 있는 가게만 (`recommend_public_default=true`) |
| **report_kpi.py** | 요약카드로 **오늘의 숫자 리포트** 자동 작성 |

> “D1 최신화” = **낡은 요약카드를 버리고, 새 명부·새 메모로 카드를 다시 뽑는다.**

---

## 왜 하냐

1. Lightsail에서 status를 계속 받는데, **D1 CSV가 예전 as_of**면 ②는 옛날 가용률을 봄  
2. info(좌표·limitYn·이름)가 바뀌었는데 master가 옛것이면 **공용/아파트 분류가 틀림**  
3. `usage_level`이 없으면 미관측·낡은 상태일 때 ②가 쓸 **보조 신호**가 없음  
4. KPI에 **전체만** 있으면 아파트·회원제까지 섞여 “갈 수 있는 곳” 숫자가 아님 → **공용만** 따로 셈

## 단어 정리

| 말 | 뜻 |
|---|---|
| **D1** | `station_feature_snapshot` — 충전소(`statId`) **1행** · 기준시각 `as_of_ts` |
| **info 반영** | EvCharger **시설 목록**으로 `charger_master`를 다시 만들고, 그걸 D1 입력으로 씀 |
| **usage_level** | 대구시 이용현황 기반 **적음/보통/많음** (F18). 실시간 가용 **덮어쓰기 금지** |
| **공용 후보** | `access_restricted=false` → `recommend_public_default=true` (기본 추천 풀) |
| **report_kpi.py** | D1·루프 상태를 읽어 `KPI_보고서.md`를 **덮어씀** (공용 섹션 포함) |

정본 스키마: [`../스키마/데이터셋_명세.md`](../스키마/데이터셋_명세.md)  
이용제한: [`이용제한_필터.md`](./이용제한_필터.md)  
1·2번 작업 기록: [`../품질보고/다음할일_1_공용집계_2_이용강도.md`](../품질보고/다음할일_1_공용집계_2_이용강도.md)

## 흐름 (그림)

```text
[최신 EvCharger info]
        │
        ▼
  charger_master 재빌드     ← “info 반영”
        │
        ▼
[status 스냅 as_of]  +  [이용강도 표]  +  [주차·돌발 조인 등]
        │                    │
        └────────┬───────────┘
                 ▼
     D1 = station_feature_snapshot_latest.csv
                 │
                 ▼
          report_kpi.py
                 │
                 ▼
     KPI_보고서.md  (§ 공용 후보만 …)
                 │
                 ▼
              ②가 읽음
```

## 실제로 치는 명령 (repo 루트)

순서만 지키면 됨. **점수는 안 나옴.**

```bash
# 1) (필요 시) info → master 다시
python apps/data-pipeline/evaluation/personal/experiments/SANDBOX_20260716_preprocess_pipeline/src/preprocessing/run_pipeline.py

# 2) (필요 시) 이용강도 표 갱신
python apps/data-pipeline/processing/features/build_usage_history_features.py

# 3) D1 다시 뽑기  ← 핵심
python apps/data-pipeline/evaluation/personal/experiments/SANDBOX_20260716_preprocess_pipeline/src/preprocessing/build_d1_snapshot.py

# 4) 공용 숫자 포함 KPI 문서 갱신
python apps/data-pipeline/processing/analysis/report_kpi.py
```

info·이용강도가 **이미 최신**이면 3→4만 해도 됨.  
애매하면 1→2→3→4 전부.

- 점수·가중치 숫자 확정 (②)
- 소통 linkspeed를 억지로 소에 조인 (별도)
