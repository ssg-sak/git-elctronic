## 1. 한 줄 요약

> **소통(linkspeed)** = 대구 도로 **1,960개 링크**의 **지금 속도·혼잡·통행시간** 스냅샷.  
> **돌발(dgincident)** = **지금 진행 중인** 사고·공사·통제 (건수는 시각마다 1~수십 건).  
> UTIC(경찰청) 전국 피드 대신 **대구 원천 + `DATA_GO_KR_KEY` 하나**로 받을 수 있음.

## 3. 소통 데이터가 뭐냐 (linkspeed)

### 3.1 비유

충전소까지 **차로 갈 때 도로가 막히는지** 보려는 데이터입니다.

- **한 행** = 도로 **한 구간(링크)** 1개  
  예: `수성네거리 → 수성교남단` on `달구벌대로`
- **갱신** = ATMS(대구 교통)가 찍은 시각 (`atmsTm`, 예: `20260722163500`)
- **우리 수집 시각** = `fetchedAt`

### 3.2 컬럼 설명

| 컬럼 | API 원본 | 뜻 |
|---|---|---|
| `linkId` | `STD_LINK_ID` | 링크 고유 ID (조인 키 후보) |
| `roadName` | `ROAD_NM` | 도로명 |
| `sectionNm` | `SECTION_NM` | 구간명 (시작~끝 시설) |
| `startNodeNm` / `endNodeNm` | `START_FAC_NM` / `END_FAC_NM` | 구간 양 끝 이름 |
| `distanceM` | `DIST` | 구간 길이 (m) |
| `speedKph` | `LINK_SPEED` | **현재 통행속도 (km/h)** |
| `travelTimeSec` | `LINK_TIME` | 구간 통과 예상 시간 (초) |
| `congGrade` | `SECTION_INFO_CD` | **1=원활, 2=지체, 3=정체** |
| `congGradeNm` | (파생) | 원활 / 지체 / 정체 |
| `atmsTm` | `ATMS_TM` | ATMS 기준 시각 |
| `traffic_source` | — | `daegu_live` |
| `isMock` | — | `false` |

### 3.3 7/22 추출 통계 (예시)

| 항목 | 값 |
|---|---|
| 링크 수 | **1,960** |
| 평균 속도 | ~35 km/h (추출 시점) |
| 원활(1) | ~1,070 |
| 지체(2) | ~742 |
| 정체(3) | ~148 |

### 3.4 충전 추천에 쓰는 법 (MVP)

| 쓸 수 있음 | 아직 어려움 |
|---|---|
| “이 시간대 대구 전체 혼잡도” 요약 | 링크 **좌표 없음** → 충전소와 바로 거리 조인 불가 |
| 후보 경로(TMAP)와 **링크 ID 매칭** (②·백엔드) | mock 12건처럼 lat/lng 없음 |
| D1 보조: `traffic_source=daegu_live` 플래그 | 링크맵·공간조인 **후속 작업** |

**ETA(이동시간)** 는 MVP에서 **TMAP 실시간 경로**가 정본.  
소통 데이터는 **“도로가 원활한 편인가”** 보조·검증용.

## 4. 돌발 데이터 (dgincident) — 같이 뽑음

| 컬럼 | 뜻 |
|---|---|
| `incidentId` | 돌발 ID |
| `incidentTitle` | 사고/공사/통제 내용 |
| `location` | 위치 문자열 |
| `coordX`, `coordY` | **경도·위도** (돌발은 좌표 있음) |
| `linkId` | 관련 도로 링크 |
| `startDate` / `endDate` | 시작·종료 시각 |

**UTIC 돌발 vs 공공 돌발**

| | UTIC | 대구 dgincident |
|---|---|---|
| 범위 | 전국 → 대구 필터 | **대구만** |
| 7/22 대구 건수 | ~9 | ~1 (스냅샷) |
| 키 | `UTIC_API_KEY` + IP | `DATA_GO_KR_KEY` |
| 소통 | ❌ | linkspeed **1,960** |

돌발만 보면 양이 비슷하지만, **소통 링크 1,960개** 때문에 공공 패키지가 훨씬 큼.
