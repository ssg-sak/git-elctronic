## 1. 어떤 지표를 볼까

| 지표 | 분모 | 쓸 곳 | 대구 전체 대표? |
|---|---|---|---|
| 스냅샷 `stat==2` / 행 수 | **이번 period 변경분**만 | 루프 건강·당일 추세 | **❌** |
| D1 `availability_ratio_observed` | 관측된 충전기만 | 소별 비교·② 입력 | △ (관측분 기준) |
| D1 `available_count / total_chargers` 전역 | 전체 충전기 (미관측=비가용처럼 보임) | 참고만 | 낮아 보임 = **정상** |
| D1 `has_confirmed_available` | 충전소 수 | “확정 가용 ≥1대” 커버리지 | ✅ 해석 가능 |
| D1 `unobserved_rate` | 소별 충전기 | 수집 커버·미확인 비율 | 함께 볼 것 |

**정본 조합 (핸드오프·보고):**  
`availability_ratio_observed` + `unobserved_rate` + (선택) `has_confirmed_available`  
스냅샷 67%를 “대구 가용률 67%”라고 **쓰지 말 것**.

코드: `2`/`02` = 충전대기 = `AVAILABLE` ([`상태코드_매핑.md`](../스키마/상태코드_매핑.md)).

## 2. 신뢰도 임계값 (팀 공통 · AGENTS)

| 경과 (`status_age` / 관측 경과) | 등급 | 의미 |
|---|---|---|
| ≤ 5분 | HIGH | 신선 |
| 5~15분 | NORMAL | 보통 |
| > 15분 | CHECK_REQUIRED | 확인 필요 · 감점 |
| 미관측 | (UNOBSERVED 등) | **사용 불가로 치지 않음** |

루프가 10분이면 HIGH만 많을 거라 기대하지 말고, **NORMAL+HIGH vs CHECK** 비중을 본다.  
이중 신선도: `reliability_grade_effective` = `statUpdDt` 등급과 `observation_age` 등급 중 더 좋은 쪽 ([`피처_카탈로그.md`](../스키마/피처_카탈로그.md) F05b).

## 3. “이상하다” 판별

| 신호 | 해석 |
|---|---|
| 스냅샷 가용률이 회차마다 **±0.15 이상** | period 샘플 변동·공백·한도 의심 |
| 스냅샷 ~0.7 · D1 관측가용 ~0.55 · 전역 ~0.3 | **정상** (분모 다름). 버그 아님 |
| `unobserved_rate` 평균 **> 0.5** 지속 | 커버·period 점검 |
| 일일 점검 gap > 0 또는 간격 ≫ 12분 | 루프 중단·PC 슬립 |
| D1 `as_of_ts`가 수 시간 전 | “지금” 숫자가 아님 → 재빌드 후 해석 |

---

## 4. MVP에서 의미 있다고 보는 최소선

| 항목 | 기준 |
|---|---|
| 루프 | 회차 누적 · 간격 ≈10분 · gap 없음 |
| 확정 가용 소 | `has_confirmed_available` 대략 **절반 이상**이면 재료로 쓸 만함 |
| 단정 금지 | 가용률 **절대값 하나**로 좋다/나쁘다 말하지 말 것 → 요일·시간·충전기 수 버킷 (EDA E3 등) |
