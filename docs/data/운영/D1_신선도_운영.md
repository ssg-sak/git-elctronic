# D1 신선도 운영 (observation_state)

| 항목 | 내용 |
|---|---|
| **작성** | 2026-07-30 |
| **담당** | AI·데이터 ① |

## 문제

D1을 `datetime.now()`로 빌드하면, Lightsail pull이 끝난 뒤에도 **재빌드 지연분**이 `observation_age`에 더해져 전부 STALE처럼 보인다.

## 규칙

| 모드 | 플래그 | 언제 |
|---|---|---|
| **핸드오프/분석 (기본)** | `--as-of latest-snap` | 최신 status CSV 파일명의 `YYYYMMDD_HHMMSS`를 `as_of`로 사용 |
| **라이브 시점 점검** | `--as-of now` | 벽시계 기준 (pull이 15분 이상 전이면 STALE이 정상) |

```bash
python .../build_d1_snapshot.py              # latest-snap
python .../build_d1_snapshot.py --as-of now  # wall clock
```

## 기대 분포 (latest-snap, pull 직후)

| observation_state | 의미 |
|---|---|
| FRESH | effective grade HIGH (관측 ≤5분) |
| NORMAL | ≤15분 |
| STALE | 관측은 있으나 15분 초과 / CHECK_REQUIRED |
| UNOBSERVED | 해당 as_of에 status 없음 |

**운영:** pull → (선택) UTIC/주차 → **즉시** D1(`latest-snap`) → 팀 공유.  
라이브 API는 백엔드가 요청 시각 기준으로 다시 신선도를 본다.
