## 1. PASS / WARN / FAIL이 뭔 뜻인가

자동 검사가 데이터에 대해 **세 가지 신호등**을 켠다.

| 판정 | 한 줄 | 넘겨도 되나? |
|---|---|---|
| **PASS** | 약속한 기준을 통과했다 | 그 검사는 OK |
| **WARN** | 치명적은 아니지만 **한계·주의·추가 처리**가 있다 | **넘길 수 있다.** 단, 한계를 같이 말해야 한다 |
| **FAIL** | 약속한 기준을 깨뜨렸다 (키 중복 폭주, 좌표 붕괴 등) | **넘기면 안 된다.** 고쳐야 함 |

이번 리포트: **FAIL 0 · WARN 10 · PASS 17**.

### WARN을 잘못 읽으면

| 잘못된 말 | 올바른 말 |
|---|---|
| “경고가 있어서 데이터 못 씀” | FAIL이 없어서 **인수인계는 가능**. WARN은 **어떻게 쓰면 되는지** 표시 |
| “WARN이니까 품질 나쁨” | 커버리지가 얇거나, 집계 전에 dedupe가 필요하거나, 목표 주기를 못 맞춘 **운영·범위 한계**인 경우가 많음 |
| “PASS만 있으면 완벽” | PASS는 그 검사 항목만 통과. 주차·usage는 여전히 보조(HOLD) |

**한 줄로:** WARN = “데이터셋 폐기”가 아니라 **“쓸 때 이 조건을 지켜라”**.

## 2. 미팅에서 30초로 말하는 법

> 자동 검사 27개 중 실패(FAIL)는 0건입니다.

## 4. 영역별로 묶어서 기억

### 상태·수집 (1~3, 10) — “어떻게 모았는가”

- 긴 공백이 있었다 → **gap-safe**로 이미 대응.
- 과거 스냅 중복 → **읽을 때 dedupe**.
- 신선도 WARN → 넘기는 산출물에 **갱신 시각·신뢰도 등급**을 같이.

### 주차 (4~6) — “얇고 조심해서”

- realtime은 일부 lot만.
- 공간 매칭 ≠ 실시간 커버.
- → **보조 설명, 점수화·본선 피처 금지(HOLD).**

### 도시소통 (7~8) — “맥락이지 ETA가 아님”

- 도시 혼잡 패턴은 볼 수 있음.
- 경로 ETA·소별 “막혀서 실패” 인과는 **이 데이터로 주장 금지.**

### 이용이력 (9) — “표본이 작다”

- 4.8% 커버 → 장기 prior 정도.
- → **HOLD.** 전 소에 일반화 금지.

## 5. FAIL 0인데 WARN이 있는 이유 (한 장)

```
FAIL 0  →  키·좌표 같은 “데이터셋 붕괴”는 없다  →  넘겨도 된다
WARN 10 →  범위·운영·보조데이터 한계가 있다   →  한계를 문서로 고정한다
```

DA① 산출물의 태도:

1. 경고를 **숨기지 않는다** (그림에 WARN 막대가 있는 이유).
2. WARN을 **HOLD/보조/처리 규칙**으로 바꾼다.
3. 추천 점수·도착 성공확률은 WARN과 무관하게 **아직 DA②/라벨 영역**이다.
