| **핵심** | 모든 실데이터를 보관·분석할 수는 있어도, 모두가 현재 추천 입력은 아니다. |

## 1. 먼저 지킬 분리 원칙

```text
현재 시점의 값       → D1 / 최신 추천 보조
과거 시점의 이력     → 시간대 프로파일·EDA·향후 학습
거의 변하지 않는 값  → 정적 컨텍스트·조인 키
mock·stale·미조인    → 검증용 또는 제외
```

- `as_of_ts`가 현재 시각이라고 해서 모든 원천이 그 시각까지 최신이라는 뜻은 아니다.
  D1은 status의 `status_age_minutes`·`observation_age_minutes`를 노출한다.
  주차·돌발은 최신 export/loop 파일의 `fetchedAt`·`collected_at`으로 별도 신선도를 확인한다.
- 시계열의 미래 행을 현재 추천이나 학습 feature에 섞지 않는다.
- `null`은 대개 “미관측/미조인”이며, `0` 또는 “사용 불가”와 다르다.

| Team5 주차 realtime 이력 | `docs/data/extracted/parking/team5_full_snapshot_*/parking_realtime_status.csv` + `incremental/` | 주차장×10분 배치 | 주차 혼잡 EDA·향후 profile | 2주 이상 누적 전에는 ‘평소 혼잡도’ 확정 금지 |

### Team5 주차 누적 방식

- DB 원천은 Team5가 10분 배치를 보관한다.
- DA①은 `export_team5_parking_incremental.py`로 **마지막 `id` 이후 새 행만 읽기 전용 export**한다.
- 로컬 Windows Task Scheduler `EVSafeCharge-Team5ParkingIncremental`가 매일 03:20 KST에
  `run_team5_parking_daily.ps1`을 실행한다. Team5 DB에 쓰지 않으며, PC가 켜져 있어야 실행된다.
- 최신 pointer와 전체 이력을 구분한다. `*_latest.csv`에 이력 전체를 섞지 않는다.

## 4. 서빙 전달 정본

| 산출 | 행 단위 | 전달 용도 | 반드시 같이 전달할 것 |
|---|---|---|---|
| `station_feature_snapshot_latest.csv` | `statId` 1행 | 현재 추천용 feature snapshot | `as_of_ts`, `status_age_minutes`, `observation_age_minutes`, mock/source flag |
| `kpi_report_latest.json` | 보고서 | 배포 전 품질 확인 | KPI PASS/FAIL 원인 |
| `station_feature_snapshot_sample_30.csv` | 표본 | ②·BE 컬럼 확인 | 전체 CSV의 대체본이 아님 |
| D1 설명 팩 | 문서·PNG | 팀 설명·발표 | `D1_최신화의미_YYYYMMDD/README.md` |

서빙 담당자는 D1을 읽되, 외부 런타임 API/DB 최신값을 붙일 때는 **시각과 소스 플래그를 보존**한다.
DA①은 추천 가중치·최종 순위 계산을 확정하지 않는다.

## 5. 분석·학습 전용

| 산출 | 용도 | 현재 상태 |
|---|---|---|
| D2 gap-safe panel | 상태 변화·시간대 가용률·향후 ML | 현 패널은 과거 구간. 최신 loop1 누적 후 재빌드 필요 |
| status/traffic/parking hourly profile | 요일×시간 패턴 | status·traffic은 누적 중, 주차는 초기 3일 |
| 충전이력 station-hourly profile | 과거 수요 신호 | 만들 수 있으나 `statId` mapping confidence를 별도 보관 |

학습 split은 시간 순서로 나눈다. 이후 시점의 status·주차·교통을 과거 행의 feature에 붙이면 leakage다.

1. D1 `statId` 중복 없음, 필수 컬럼·허용 범위 확인

3. `parking_is_mock=false`, `traffic_is_mock=false` 확인
