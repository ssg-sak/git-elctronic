## 1. 파일 종류

| 파일 패턴 | API | 한 줄 설명 |
|---|---|---|
| `daegu_charger_info_*.csv` | getChargerInfo | 충전소·충전기 **정적 정보** (약 2.5만 행) |
| `daegu_charger_status_*.csv` | getChargerStatus | **최근 N분 안에 상태가 바뀐 충전기만** (수백 행) |

> status 한 파일 ≠ info 전체. **같은 충전기**는 `statId` + `chgerId`로 info와 조인한다.

**저장 위치**

| 구분 | 경로 |
|---|---|
| info (일별) | `docs/data/extracted/daily/YYYY-MM-DD/` |
| info (단발) | `docs/data/extracted/charger/info/daegu_charger_info_*.csv` |
| status (틱별 정본) | `.../SANDBOX_20260717_status_periodic_collection/data/snapshots/` |
| status (일별 통합) | `.../SANDBOX_.../data/daily/YYYY-MM-DD/` |

## 2. 충전기 기본정보 (`daegu_charger_info_*`)

**1행 = 충전기 1대**

| 영문 컬럼 | 한글 이름 | 설명 | 예시 |
|---|---|---|---|
| `statId` | 충전소 ID | 공공 API 충전소 고유 번호. 조인 키 | `ME183050` |
| `statNm` | 충전소명 | 충전소 이름 | `대구보건환경연구원` |
| `addr` | 주소 | 도로명·지번 주소 | `대구광역시 수성구 무학로 215, …` |
| `lat` | 위도 | WGS84 위도 (도) | `35.8296797` |
| `lng` | 경도 | WGS84 경도 (도) | `128.6320054` |
| `chgerId` | 충전기 ID | 충전소 안에서 충전기 번호 (`01`, `02` …) | `01` |
| `chgerType` | 충전 방식 코드 | 아래 **충전기 타입 표** 참고 | `06` |
| `output` | 출력 | 충전기 출력 (kW, 문자열) | `50` |
| `useTime` | 이용 시간 | 운영·이용 가능 시간 | `24시간 이용가능`, `08:00~21:00` |
| `busiNm` | 운영기관 | 충전소 운영 사업자 | `기후에너지환경부` |
| `parkingFree` | 주차 무료 여부 | `Y`=무료, `N`=유료/미제공 | `Y` |
| `limitYn` | 이용 제한 여부 | `Y`=제한 있음, `N`=제한 없음 | `N` |
| `delYn` | 삭제(폐지) 여부 | `Y`=등록 제외·삭제, `N`=정상 | `N` |
| `fetchedAt` | **우리가 수집한 시각** | API를 호출해 파일에 저장한 시각 (KST) | `2026-07-17 19:41:08` |

## 3. 충전기 상태 (`daegu_charger_status_*`)

**1행 = 특정 시각에 “상태가 바뀐” 충전기 1대**

| 영문 컬럼 | 한글 이름 | 설명 | 예시 |
|---|---|---|---|
| `statId` | 충전소 ID | info와 동일 | `ME178137` |
| `statNm` | 충전소명 | status API에서는 **자주 비어 있음** → 이름은 info 참고 | *(빈칸)* |
| `chgerId` | 충전기 ID | info와 동일 | `01` |
| `stat` | **상태 코드** | 충전기 현재 상태 (숫자). 아래 **상태 코드 표** | `2` |
| `statUpdDt` | **상태 변경 시각** | 충전기/운영사가 상태를 마지막으로 갱신한 시각 (API 원본) | `20260722153443` |
| `fetchedAt` | **우리가 수집한 시각** | 이번 API 호출·스냅샷 저장 시각 (KST) | `2026-07-22 15:40:33` |
| `snapshotId` | 스냅샷 ID | 루프 수집 회차 ID (`YYYYMMDD_HHMMSS`) | `20260722_154033` |
| `pageNo` | API 페이지 번호 | getChargerStatus 페이지네이션 순번 | `1` |

### ⚠️ `fetchedAt` vs `statUpdDt`

| | `fetchedAt` | `statUpdDt` |
|---|---|---|
| **누가 찍었나** | 우리 수집기 | 충전기/운영 시스템 |
| **쓰는 곳** | “언제 조회했는지”, 스냅샷 시각 | **신뢰도·데이터 신선도** (5분/15분 등급) |
| **형식** | `2026-07-22 15:40:33` | `20260722153443` (연월일시분초 붙임) |

**혼용하지 않는다.** “15분 전에 확인됨”은 `statUpdDt` 기준이다.

## 4. 상태 코드 (`stat`) — 숫자 → 한글

EvCharger API 원천값. 서비스·분석에서는 [상태코드_매핑.md](./상태코드_매핑.md)의 **표준 5값**으로 변환해 쓴다.

| `stat` 값 | API 의미 | 한글 (일상 표현) | 추천·가용률 집계 |
|---:|---|---|---|
| `1` | 통신이상 | **미확인** (연결 안 됨) | 사용 가능 아님 · 고장으로 세지 않음 |
| `2` | 충전대기 | **사용 가능** | ✅ 가용 |
| `3` | 충전중 | **사용 중** | 사용 중 |
| `4` | 운영중지 | **고장·중지** | ❌ 비가용 |
| `5` | 점검중 | **점검 중** | ❌ 비가용 |
| `9` | 상태미확인 | **미확인** | 사용 가능 아님 · 고장으로 세지 않음 |

> **이번 스냅샷에 행이 없다** = “고장”이 아니라 **“그 10분 안에 상태 변경 없음”** (미관측).

## 7. 조인·행 해석 (자주 헷갈리는 점)

```text
info  25,000행  ── statId + chgerId ──  status  500행 (한 틱)
         │                                    │
    충전기 전체 목록                    최근 10분 변경분만
```

| 질문 | 답 |
|---|---|
| status에 없는 충전기는? | 그 틱에 **변경 없음**. info에는 있음 |
| info에 없는 statId는? | 신규·오타·수집 시점 차이. 품질 점검 대상 |
| 일별 status 통합 CSV | 그날 모든 틱을 `snapshotId` 컬럼과 함께 이어 붙인 long table |

## 8. 예시 한 줄 읽기

**info**
```csv
"ME183050","대구보건환경연구원",…,"01","06","50","08:00~21:00",…,"2026-07-17 19:41:08"
```
→ 충전소 `ME183050`의 1번 충전기. DC복합(06), 50kW, 08~21시 운영. 7/17 19:41에 수집.

**status**
```csv
ME178137,01,2,,20260722153443,2026-07-22 15:40:33,20260722_154033,1
```
→ 충전소 `ME178137` 1번 충전기. **사용 가능(2)**. 상태는 15:34:43에 변경됨. 15:40:33 스냅샷에서 수집.
