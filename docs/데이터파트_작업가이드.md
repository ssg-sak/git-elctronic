## 3. 역할 구분

### DA➀ 데이터·파이프라인

- 원천 구조·데이터 사전 · 상태코드 표준화 · 품질 점검
- **공백 안전 패널** 재구성 · EDA · 특성·데이터셋(D1/D2)
- **하지 않음:** 점수·위험도·추천 이유·모델 실험·서빙

### DA➁ 모델·평가·서빙

- 문제 정의 · 거리순 baseline · 규칙 점수 · 위험도·추천 이유
- 모델·평가 · 백엔드 추론 함수

### 행 단위 (필수 합의)

> **기준시각 T × 충전소 S** 의 상태·주변 조건

예: `2026-07-20 10:30 / MOCK-ST001 / (도착 15분 후 사용 가능 여부)`

저장소 정본: [`docs/data/스키마/데이터셋_명세.md`](./data/스키마/데이터셋_명세.md) — D1=스냅샷 1행/소, D2=소×시각 패널.

## 4. DA➀ 작업

### 4.1 원천 데이터 사전

| 공식 컬럼 | 의미 | 내부(EvCharger) 대응 |
|---|---|---|
| `stationId` | 충전소 ID | `statId` |
| `chargerId` | 충전기 ID | `chgerId` |
| `status` | 표준 상태 | `stat` → 매핑 |
| `statusUpdatedAt` | 원천 갱신 시각 | `statUpdDt` |
| `observedAt` | 우리 수집 시각 | `fetchedAt` / `snapshotId` |
| `latitude` / `longitude` | 좌표 | `lat` / `lng` |

정본: [`docs/data/스키마/데이터_사전.md`](./data/스키마/데이터_사전.md)

### 4.2 상태코드 표준화

**API·상태 표준 4값** (본 가이드):

| 표준값 | 의미 |
|---|---|
| `AVAILABLE` | 충전 가능·대기 |
| `CHARGING` | 충전 중 |
| `OUT_OF_SERVICE` | 고장·점검·통신오류 등 사용 불가 |
| `UNKNOWN` | 미확인·해석 불가 |

**내부 5값** (세분화·EDA): `OUT_OF_ORDER` · `UNDER_INSPECTION` — [`상태코드_매핑.md`](./data/스키마/상태코드_매핑.md)

코드: `processing/status_standard.py` · `processing/cleansing.py`

### 4.3 실 상태 이력 (정본)

- 스냅샷: `docs/data/loops/loop1/snapshots/` (Lightsail pull)
- 현재표/시간표: `build_d1_snapshot.py` · `build_d2_panel.py`
- 품질: `validate_recommendation_inputs.py` · `monitor_recommendation_input_quality.py`

### 4.4 품질 점검

실 패널·스냅샷 기준. 목 `mock_history_report` 경로는 **폐지**.

### 4.5 공백 안전 패널

원칙: 시간순 정렬 → 충전기별 마지막 상태 유지 → **시점당 충전기 1표** → **25분 초과 공백** 시 구간 분리

코드·테스트: `processing/features/gap_safe_panel.py` · `evaluation/tests/test_gap_safe_panel.py`

### 4.6 특성 생성

| 가이드 | 현재표/시간표 컬럼 |
|---|---|
| `available_ratio` | `availability_ratio_observed` |
| `data_freshness_minutes` | `observation_age_minutes` / `status_age_minutes` |
| `available_count` | `available_count` |
| `total_chargers` | `total_chargers` |

코드: `processing/features/` · sandbox `build_d1_snapshot` / `build_d2_panel`
