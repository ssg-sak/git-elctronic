## 1. 회의 시작하자마자 정할 7가지

빈칸은 회의에서 채운다.

| # | 질문 | 제안 | 우리 결정 |
|---|---|---|---|
| 1 | 추천 점수 비중은 어떤 문서 따를까? | **루트 AGENTS** (가용40 · 신뢰20 · 이동15 · 대기15 · 편의10) | |
| 2 | 실패 위험은 몇 단계? | **3단계** (낮음·보통·높음) | |
| 3 | 주차는? | 지금은 **실보장 안 함**. 화면에 “실험/없음” 표시. **7/23 KOTSA** 보고 다시 | |
| 4 | 교통은? | **돌발(사고·공사)은 씀**(UTIC). 도로 속도(소통)는 **나중에** | |
| 5 | AI 학습(머신러닝)은? | MVP에서는 **안 함**. 상태 데이터 쌓인 뒤 | |
| 6 | 요구사항 문서는 뭐가 정본? | **종합 정의서 md**. SFR 표는 체크용 | |
| 7 | 가짜(mock) 데이터는? | 실험용으로 **남겨둠**. 실서비스 표(D1)에는 **가짜 거리 넣지 않음** | |

## 2. 누가 뭘 하나 (쉬운 버전)

| 역할 | 이번에 하는 일 | 이번에 안 하는 일 |
|---|---|---|
| **프론트** | 지도, 목록, 상세, 필터, “실데이터/실험용” 표시, 한계 안내 문구 | 점수 계산, 공공 API 직접 호출, 완벽한 관리자 화면 |
| **백엔드** | 추천 API, 길 예상시간(TMAP), 장애 시 대체, API 키 보관 | 예약·결제, 위치 영구 저장, 무거운 AI 서버 |
| **데이터 수집** | 충전소·상태 공식 수집, 스케줄 | 전처리 규칙 마음대로 바꾸기, 키 한도 무시하고 중복 호출 |
| **AI·데이터 ①** | 데이터 정리, 품질, 피처, D1/D2, 돌발 붙이기, 문서 | 추천 점수·순위·이유 문장, 화면, ETA 호출 |
| **AI·데이터 ②** | **규칙으로 점수·위험·추천 이유** 만들기 | 지금은 본격 학습모델(LightGBM 등) |

## 3. 전원 동의: MVP에서 빼자

이런 건 **이번에 안 만든다.**

- 예약, 결제, 충전기 원격 조작
- 차 배터리 직접 연동
- 전국 서비스
- “주차 자리가 지금 몇 개”를 **진짜처럼 보장**
- 즐겨찾기, 알림, 사용자 제보 (나중에)
- AWS 올려서 대구 주차 API만 쓰기 (비용 — **회의에서 최종 확인**)

## 6. 역할별로 “이건 손대지 마”

### 프론트
- 점수·위험을 **직접 계산**하지 말 것 → API 결과만 보여 주기
- 공공 API를 브라우저에서 **직접** 치지 말 것 → 키 샘
- 관리자 화면 크게 만들지 말 것

### 백엔드
- 추천 비중을 코드에 박아 두고 잊지 말 것 → ②랑 맞출 것
- MVP에 AI 서버 올리지 말 것 → 규칙 점수면 됨
- 예약·결제, 위치 DB 장기 저장 하지 말 것

### 수집
- ①이 PC에서 도는 수집이랑 **키 한도 싸워서** 막 호출하지 말 것
- 주차 API가 로컬에서 안 되는 걸 “버그”로만 보지 말 것 (IP 제한)

### AI·데이터 ①
- 점수·순위·추천 문구 만들지 말 것 → **②**
- ETA 호출하지 말 것 → **백엔드**
- 가짜 주차 거리를 실데이터처럼 넣지 말 것

### AI·데이터 ②
- 상태코드·전처리 규칙을 혼자 바꾸지 말 것 → **① 문서**
- MVP에서 학습모델·랭커 돌리지 말 것
- “상태 모름”을 “사용 불가”로 넣지 말 것
