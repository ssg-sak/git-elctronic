## 2. “왜” — 직선거리만 쓰면 연동이 깨진다

추천 점수에 **이동시간 15점**이 있다.  
여기다 직선거리를 넣으면:

1. **시간 숫자가 거짓** → 사용자에게 “11분”이라고 말할 수 없음  
2. **순위가 뒤집힘** → 가까운데 일방통행이라 더 오래 걸리는 곳이 1등  
3. 그 위에 useTime까지 안 걸면 **문 닫힌 곳**이 1등

그래서 DA가 TMAP을 **수집 루프로 돌린 게 아니라**,  
“백엔드가 TMAP을 붙여야 하는 이유”를 **15건 샘플로 증명**한 것이다.

### 증거 ① 시간이 다름

![직선 vs TMAP](data/analysis/tmap_eta_sample_20260723/figures/01_직선환산_vs_TMAP_ETA.png)

- 동대구복합환승센터: 직선 ~**0.7분** → TMAP **9분**
- 같은 “가까운 15곳”인데 실제 ETA는 **2~9분**

### 증거 ② 순위가 바뀜

![순위 뒤집힘](data/analysis/tmap_eta_sample_20260723/figures/02_순위_뒤집힘.png)

직선 1등이 TMAP에선 뒤로 밀릴 수 있음 → **정렬 기준은 ETA**.

### 증거 ③ 도로가 훨씬 김

![직선 vs 도로 km](data/analysis/tmap_eta_sample_20260723/figures/03_직선거리_vs_도로거리.png)

점선(직선=도로) 위쪽 = 우회·진입로 때문에 도로 km ≫ 직선 km.

## 3. useTime과의 연동 (TMAP만으로 끝이 아님)

```
TMAP ETA ──► 도착시각 ──► useTime 필터 ──► 그다음 점수
```

![도착 게이트](data/analysis/tmap_eta_sample_20260723/figures/05_도착_useTime_게이트.png)

| 게이트 | 의미 | 추천 쪽 동작 |
|--------|------|----------------|
| KEEP | 도착 때 영업 | 후보 유지 |
| DROP | 도착 때 마감 | 탈락/최하위 |
| REVIEW | UNKNOWN | **열린 것으로 치지 말 것** |

오늘 샘플(17:01)은 전부 KEEP.  
**연동 포인트는 “지금은 KEEP”이 아니라, ETA가 있어야 도착 시각을 계산할 수 있다**는 것.
