# 02. 역할별 확인 · 토론 (서로 말하기)

회의 **C구간**. ①이 일방 설명하지 말고, **역할마다 확인하고 질문**한다.

진행 팁: 사회자가 역할 순서대로 “확인 질문”을 읽고, 해당 담당이 답한다.

---

## 공통 — 전원 확인 (2분)

| # | 확인 문장 | 기대 답 |
|---|---|---|
| G1 | 현재표 = 충전소 1행 “지금”, 시간표 = 충전소×시각. 점수는 표에 없다. | 전원 “맞다” |
| G2 | ① 상태 코드 `DA1_READY…`는 **데이터 준비 완료**이지 모델 성능 보증이 아니다. | 전원 “맞다” |
| G3 | 말할 때 D1/D2 대신 **현재표/시간표**를 쓴다. | 전원 “맞다” |

---

## DA② (모델·점수) — 토론

| # | ①이 묻는 것 | ②가 답/결정할 것 |
|---|---|---|
| M1 | 최종 **9피처**를 1차 학습·규칙 입력으로 받을 수 있나? | 수용 / 수정 요청 |
| M2 | 타겟 `target_available_at_arrival` 정의에 이견 있나? | 합의 / 재정의 |
| M3 | HGB 적합 수치를 **운영 성능**으로 오해하지 않기로 하나? | 예 |
| M4 | HOLD(주차·usage·UTIC)를 점수에 **넣지 않기** — 동의하나? | 동의 / 예외 |
| M5 | 학습 ETA=동대구 고정, 서빙 ETA=유저 TMAP — 평가 설계에 반영할 건가? | 일정·방법 |
| M6 | 다음으로 ②가 주는 산출물은? (규칙 점수 / 모델 / 평가 리포트) | 기한 |

②가 ①에게 물을 수 있는 예:

- 시간표 갱신 주기·재빌드 누가 돌리나?
- 라벨 parquet 컬럼 사전 어디인가? → `스키마/피처_카탈로그` · `전체_데이터셋_컬럼_사전`

---

## 백엔드 — 토론

| # | ①이 묻는 것 | BE가 답/결정할 것 |
|---|---|---|
| B1 | 추천 요청 시 **현재표 as_of** + **유저 TMAP ETA** 결합 — 이 흐름으로 가나? | 예 / 대안 |
| B2 | ① 제안 필드(`freshness_flag`, `recheck_required`, `availability_guaranteed=false` 등) API에 실을 건가? | 수용 목록 |
| B3 | `availability_guaranteed`는 예약 전 **항상 false** — 응답에 넣을 건가? | 예 |
| B4 | 현재표 파일을 읽는 주체: BE 직접 / ② 라이브러리 / 배치 DB? | 선택 |
| B5 | 스키마 바꾸면 **문서+①·② 합의** 후 — 지킬 건가? | 예 |

BE가 ①에게:

- latest 파일 갱신 SLA는? → 수집 컷 기준 배치. 실시간 API는 BE·수집과 별도 합의.
- 타입은? → `packages/shared-types`는 BE·FE 주관, ①은 스키마 md 정본.
