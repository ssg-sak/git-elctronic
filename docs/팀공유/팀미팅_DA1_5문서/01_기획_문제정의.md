## 현재 문제

전기차 사용자는 지도에서 **가까운 충전소**를 고르는 경우가 많다.  
문제는 “거리상 가깝다”와 “도착했을 때 실제로 충전할 수 있다”가 같지 않다는 점이다.

- 충전기가 **사용 중**이거나 **고장·점검**일 수 있다.
- 앱에 보이는 상태가 **언제 갱신됐는지** 불명확하면 신뢰하기 어렵다.
- 이동하는 동안 상태가 바뀔 수 있어, **지금 비어 있음**만으로는 부족하다.
- 충전기 **1대**인 소와 **다수**인 소의 실패 위험이 다르다.

즉, “가까운 곳 추천”만으로는 **충전 실패 경험**을 줄이기 어렵다.

---

## 이 프로젝트로 어떻게 개선하는가

EV SafeCharge의 목표는 **도착했을 때 충전 가능할 가능성이 높은 충전소**를 고르는 것이다.

서비스가 쓰는 판단 재료(데이터 관점):

| 재료 | 왜 필요한가 |
|---|---|
| 실시간 충전기 상태 | 지금 사용 가능·사용 중·고장·점검 구분 |
| 상태 갱신 시각(신선도) | 오래된 상태는 경고·점수 반영 |
| 시간대·요일 가용 패턴 | “낮에 더 비고 밤에 더 찬다” 같은 구조 파악 |
| 충전기 대수·관측 커버 | 실패 위험·관측 신뢰 |
| 이동시간(ETA) | 도착 시점 가용 여부(라벨·점수)와 연결 |

팀 공통 점수 가중치(참고 — **산출은 DA②**):

```
충전 가능성 40% + 상태 신뢰도 20% + 이동시간 15%
+ 충전기 수·대기 위험 15% + 주차·운영·편의 10%
```

---

## DA①이 이 기획에서 담당한 것

①은 “추천 점수·화면”이 아니라 **추천이 믿을 수 있는 입력 데이터**를 만든다.

| 한 일 | 결과물 |
|---|---|
| 공공·실수집 정리 | 상태 스냅샷 약 2,960장 (최종 컷 기준) |
| 전처리·품질 | 중복 제거 · 상태코드 표준화 · gap-safe 시간표 |
| 서비스·학습용 표 | **현재표**(충전소 1행) · **시간표**(충전소×시각) |
| 검증 | EDA · KPI · 스키마 · 한계(HOLD) 문서화 |
| 모델 준비 | 최종 **9피처** · 도착 가용 **라벨** · 적합 점검 |

완료 상태: `DA1_READY_FOR_DA2_MODEL_EVALUATION`  
이후 점수·Top-N·서빙은 **DA②**, API·화면은 **백엔드·프론트**.
