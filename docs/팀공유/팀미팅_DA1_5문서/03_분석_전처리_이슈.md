## 전처리 파이프라인 (순서)

1. **중복 제거** — `(statId, chgerId)`별 최신 `statUpdDt`
2. **상태 매핑** — EvCharger `stat` 숫자 → 표준 5값
3. **gap-safe 패널** — 스냅 간격 **25분 초과**면 구간을 끊고, 그 안에서만 ffill
4. **충전소 집계** — 가용률 = 사용가능 / (사용가능 + 사용중)
5. **현재표 as_of** — `statUpdDt ≤ as_of`만 사용 · 신선도 등급 · `coord_ok`

### 상태코드 매핑 (반드시 말할 것)

| 원천 `stat` | 의미 | 표준 |
|---|---|---|
| 1 | 통신이상 | 미확인 `UNKNOWN` |
| 2 | 충전대기 | 사용 가능 `AVAILABLE` |
| 3 | 충전중 | 사용 중 `IN_USE` |
| 4 | 운영중지 | 고장 `OUT_OF_ORDER` |
| 5 | 점검중 | 점검 `UNDER_INSPECTION` |
| 9·없음 | 미확인·미관측 | `UNKNOWN` (**≠고장**) |

미관측·고장·점검은 가용률 **분모에서 제외**. 미관측을 고장으로 치면 점수가 왜곡된다.

정본: `docs/data/스키마/상태코드_매핑.md`

## 주요 이슈 3가지 (발표 핵심)

### 이슈 A — 중복·최신만

API 페이지 경계로 동일 충전기가 반복된다.  
전처리에서 **최신 `statUpdDt` 1건**만 남기지 않으면 가용 집계가 틀린다.

### 이슈 B — 긴 공백을 그대로 채우면 안 됨

수집이 끊긴 구간을 무조건 ffill하면 **가짜로 계속 비어 있는 것처럼** 보인다.  
**25분 초과 gap**은 패널을 끊는다 (gap-safe).

### 이슈 C — 신선도 CHECK가 많아도 정상일 수 있음

현재표 as_of 기준 HIGH(≤5분)는 소수, CHECK(>15분)가 다수다.  
이는 EvCharger **원천 갱신이 느린 소**가 많다는 신호이며, 기준(5/15분)을 느슨하게 바꾸지 않는다. 서비스에서는 **경고·신뢰도 감점**으로 연결한다(점수 구현은 ②).
