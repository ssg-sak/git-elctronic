## 1. 의사결정 요약

### 지금 가능한 것

- D1을 읽어 **공용·좌표 정상·확정 가용** 충전소를 후보로 생성
- `reliability_grade_effective`, `observation_age_minutes`로 신선도 경고 노출
- 충전기 수·가용 대수·운영 여부·이용 제한을 규칙 입력으로 사용
- Team5 주차·UTIC 돌발·POI·과거 이용강도는 **값 존재 시 보조 신호**로 사용
- 백엔드 TMAP ETA가 준비되면 `eta_minutes`에 런타임 값을 결합

### 지금 하면 안 되는 것

- D1의 미관측을 `available_count=0` 또는 사용 불가로 변환
- D1의 직선거리나 loop3 linkspeed를 ETA로 대체
- 주차 미조인·realtime 미보유를 “주차 불가”로 해석
- 2주 미만 이력으로 충전 성공확률/주차 혼잡도 모델을 확정
- 현재 Shadow 테스트의 표시 순서를 최종 모델 순위로 사용

## 4. 추천 요청·응답 연결

### 요청에 필요한 값

```json
{
  "userLat": 35.8714,
  "userLng": 128.6014,
  "asOf": "KST ISO8601",
  "topN": 5
}
```

### D1 후보 게이트 권장 순서

```text
1. recommend_public_default = true
2. coord_ok = true
3. is_operating_now != "N"
4. 상태/신선도는 탈락이 아니라 별도 등급·경고로 유지
5. has_confirmed_available = true 는 “즉시 충전 가능 후보” 탭의 강한 조건
6. ETA는 TMAP/백엔드에서 요청 시점에 결합
```

`has_confirmed_available=false`인 충전소를 무조건 숨길지, “다른 후보”로 남길지는 제품 UX와 ② 규칙에서 결정한다.
단, `observed_count=0`/`unobserved_rate`가 높은 경우는 **미관측**이지 사용 불가가 아니다.

### 응답 타입 목표

`packages/shared-types/src/index.ts`의 `StationRecommendation`:

```text
station, score(0~100), failureRisk(낮음/보통/높음),
reliability(높음/보통/확인필요), travelTimeSec,
distanceMeters, estimatedArrival, reason
```

현재 ①이 보장하는 입력은 D1이다. `score`, `failureRisk`, `travelTimeSec`,
`estimatedArrival`, 최종 `reason`은 ②/백엔드가 생성한다.

## 5. 핵심 필드·null 계약

| 필드 | 사용할 때 | null/주의 |
|---|---|---|
| `available_count`, `availability_ratio_observed` | 관측된 충전기 상태 | 미관측을 0으로 변경 금지 |
| `reliability_grade_effective` | UI 신뢰도·규칙 입력 | `status_age` 단독보다 이 필드 우선 |
| `is_operating_now` | 운영 중지 제외·경고 | `UNKNOWN`은 영업 중으로 가정하지 않음 |
| `access_restricted` | 기본 후보 제외 | 아파트성 이름은 보조 플래그일 뿐 단독 제외 금지 |
| `nearest_parking_m` | 실 Team5 1km 거리 | null=반경 내 미조인 |
| `parking_remaining_spaces` | 현재 주차 보조 | null=값 없음, 0과 다름 |
| `nearest_incident_m` | UTIC 돌발 보조 | 현재성은 join 최신 시각과 함께 표시 |
| `usage_level` | 과거 이용강도 보조 | `history_observed=false`면 사용 금지 |
| `eta_minutes` | 최종 이동시간 항목 | 현재 null 예약 필드, TMAP/API가 채움 |
