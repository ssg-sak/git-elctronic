## 1. 한 줄 요약

**대구 교통 소통 API가 복구됐고, 링크 1,960개 실데이터를 15분 루프로 쌓기 시작했다.**  
오늘 가장 큰 성과는 mock 12건이 아니라 **실 소통 시계열**을 확보한 것이다.

## 2. 소통 데이터 (오늘 핵심)

### 2.1 배경

| 기간 | 상태 |
|---|---|
| 7/15 ~ 7/21 | 공공 API `linkspeed` / `dgincident` → **HTTP 404** (원본 서버 장애) |
| **7/22** | **복구 확인** · 추출·루프 가동 |

404는 승인 문제가 아니라 **제공기관 서버 장애**였고, 복구 후 정상 수집 중이다.

### 2.2 무엇을 모으나

| API | 내용 | 규모 (7/22 스냅샷) |
|---|---|---|
| `linkspeed` | 링크별 속도·혼잡·통행시간 | **1,960 링크** |
| `dgincident` | 진행 중 돌발 (좌표 있음) | 수 건 (시간대별 변동) |

**소통(linkspeed)** = “지금 이 도로 구간이 얼마나 막히는가”  
충전 추천에서 **도착 지연 → 충전 실패 위험**을 보는 재료다.

### 2.3 어디에 쌓이나

```
docs/data/loops/loop3/
├── daegu_traffic_linkspeed_YYYYMMDD_HHMMSS.csv   ← 틱별 불변 스냅샷
├── daegu_traffic_linkspeed_latest.csv            ← 최신
├── daegu_traffic_incident_*.csv
└── daegu_traffic_meta_*.json
```

- **루프 스크립트:** `apps/data-pipeline/processing/loops/run_daegu_traffic_loop.py`
- **주기:** 15분 (틱당 API 2콜 · `DATA_GO_KR_KEY` 일 한도와 status 루프 공유)
- **출처:** 대구광역시 교통정보(ATMS) · 공공데이터포털

### 2.4 UTIC(돌발)과 관계

| 구분 | loop2 UTIC | loop3 대구 ITS |
|---|---|---|
| 소통(링크 속도) | ❌ (URL 404) | ✅ **메인** |
| 돌발 | ✅ D1 조인 중 | ✅ 추출만 (전환 검토) |

**D1 현재:** 돌발 = `traffic_source=utic` · `traffic_is_mock=false` · `nearest_incident_m` 실거리  
**소통:** D1 **미연동** (후속)

### 2.5 아직 안 된 것 (팀 인지 필수)

1. **링크 좌표 없음** → 충전소와 직접 거리 조인 불가  
   - 후속: 링크맵 확보 또는 TMAP 경로 매칭  
2. **D1·② 점수에 소통 피처 미반영** — 시계열만 쌓는 단계  
3. `traffic_source`를 `daegu_live`로 통합할지는 **UTIC 돌발과 병행 검증 후** 결정

## 3. 수집 루프 통일 (loop1 / loop2 / loop3)

단발 추출(`docs/data/extracted/`)과 **섞지 않는다.**

| 루프 | 폴더 | 내용 | 주기 | 실행 |
|---|---|---|---|---|
| **loop1** | `docs/data/loops/loop1/` | EvCharger **status** | 5분 | `SANDBOX_.../run_loop.py` |
| **loop2** | `docs/data/loops/loop2/` | UTIC **돌발** + 1km 조인 | 15분 | `run_utic_loop.py` |
| **loop3** | `docs/data/loops/loop3/` | 대구 ITS **소통·돌발** | 15분 | `run_daegu_traffic_loop.py` |

- **이전:** status는 SANDBOX `data/snapshots/`, UTIC는 `loops/utic/` 등 **이름·위치 혼재**  
- **이후:** status 데이터도 `loop1/`로 이전 · 경로 정본 `apps/data-pipeline/loop_paths.py`
