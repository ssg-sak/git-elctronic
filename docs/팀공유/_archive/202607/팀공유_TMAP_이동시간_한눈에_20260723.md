## 2. 왜 직선거리만 쓰면 안 되나

같은 “가까운 15곳”인데, 초록(직선 환산)은 거의 1분 안쪽, 주황(TMAP)은 **2~9분**.

![직선 환산 vs TMAP ETA](data/analysis/tmap_eta_sample_20260723/figures/01_직선환산_vs_TMAP_ETA.png)

**기억할 숫자 하나**  
동대구복합환승센터: 직선 ~**0.7분** → TMAP **9분** (도로 ~2.4km)

---

## 3. 순위가 뒤집힌다

직선으로 1등인 곳이 TMAP에선 뒤로 밀릴 수 있다 → **정렬 기준은 ETA**.

![순위 뒤집힘](data/analysis/tmap_eta_sample_20260723/figures/02_순위_뒤집힘.png)

![직선거리 vs 도로거리](data/analysis/tmap_eta_sample_20260723/figures/03_직선거리_vs_도로거리.png)

점선(직선=도로) 위에 점들이 있다 = **우회·일방통행** 때문에 도로가 훨씬 김.

---

## 4. 도착해도 문 닫혀 있으면?

이동시간만 맞추고 `useTime`을 안 보면 **마감 충전소**가 1순위가 될 수 있다.

![도착 useTime 게이트](data/analysis/tmap_eta_sample_20260723/figures/05_도착_useTime_게이트.png)

- `KEEP` = 도착 시각에 영업 → 후보 유지  
- `DROP` = 도착 시 마감 → **탈락/최하위**  
- `REVIEW` = UNKNOWN → **열린 것으로 치지 말 것**

오늘 오후 샘플은 전부 KEEP. **야간·마감 직전**에 DROP이 생김.

파서: `apps/data-pipeline/processing/features/use_time.py`

## 5. 백엔드가 붙일 때 (체크리스트)

1. 사용자 위치 → 직선거리로 1차 후보  
2. 상위 **3~5곳만** TMAP `/tmap/routes`  
3. 응답에 `eta_minutes` (DA 테이블은 null 예약)  
4. `now + eta` 로 `is_operating_now(useTime, arrive)`  
5. `N` 탈락 → 그다음 점수 정렬
