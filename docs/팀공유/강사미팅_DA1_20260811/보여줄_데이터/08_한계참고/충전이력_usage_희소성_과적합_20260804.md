# 과거 충전이력(usage) — 왜 넣었고, 왜 MVP 점수에 안 넣나 (2026-08-04)

**대상:** ② · 전원  
**한 줄:** 25년 전후 시정 충전이력 CSV는 **이미 조인·피처화·적합도 평가까지 됨**.  
다만 커버가 너무 얇아서 **과적합 위험 → MVP 기본 피처에서 제외(HOLD_SPARSE)**.

---

## 무슨 데이터?

| 항목 | 값 |
|---|---|
| 파일 | `docs/data/extracted/charger/usage/daegu_charger_usage_daily_20260331.csv` |
| 기간 | **2024-10-18 ~ 2026-03-31** |
| 행 수 | ~128,263 |
| 시정 충전소 | ~219곳 |
| EvCharger 매칭 | **201 / 219** (좌표 80m, match 91.8%) |

시정 `station_id` ≠ EvCharger `statId` → 좌표로 붙임.  
조인 자체는 잘 됨. **문제는 “시정 목록이 전체의 ~5%”** 라는 천장.

---

## 어디까지 반영됐나?

| 단계 | 상태 |
|---|---|
| 조인 | ✅ `join_usage_history_statId.csv` |
| 피처 | ✅ `sessions_per_charger`, `usage_daytype_avg`, `history_observed` |
| D1 | ✅ `usage_level`(적음/보통/많음) · 커버 **~200 / 4210 ≈ 4.75%** |
| 적합도 | ✅ `hgb_training_pipeline_20260803` 에서 단변량·호라이즌 확인 |
| 과적합 문서 | ✅ HOLD_SPARSE · MVP 제외 |

학습 패널(status 틱) 행 기준으로 이력이 있는 행은 **약 7%**, 없는 행 **약 93%**.

---

## 왜 점수 피처로 안 쓰나? (과적합)

1. **대부분이 빈칸** — 트리/규칙이 “이력 있는 소수 소”에만 맞춰지기 쉬움  
2. **있는 행만 보면 AUC가 나와도** 전체 4천 소에 일반화 안 됨  
3. **기간이 패널과 안 겹침** — 이력은 ~3월까지, 실시간 패널은 7월~ → prior일 뿐 실시간 가용 대체 불가  
4. **null을 0/평균으로 채우면** 더 위험 (결측 계약 위반)

그래서 판정은:

```text
HOLD_SPARSE → MVP_v1 features 에 넣지 말 것
보조 prior / UX 설명용만 (점수 가중치 금지)
```

## ②가 쓸 때

| 해도 됨 | 하지 말 것 |
|---|---|
| stale/미관측 소에 “예전에 붐빔” UX 힌트 | usage로 추천 점수 가중 |

| 시간분할 ablation에서 optional 실험 | “유의한데 왜 안 넣냐”로 기본 세트 강제 |
