## 2. D1 — 규칙용 스냅샷 (`station_feature_snapshot`)

### 행 단위
하나의 **`statId`** (충전소) = 1행.

### 기준시각
- 컬럼: `as_of_ts` (타임존 KST, ISO8601)
- 의미: 이 시각 기준으로 status·피처를 읽었다.
- status: `statUpdDt ≤ as_of_ts` 인 최신 관측만 사용 (미래 누수 금지).

### 필수 컬럼

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `statId` | string | PK |
| `as_of_ts` | datetime | 기준시각 |
| `lat`, `lng` | float | 좌표 (`coord_ok=true`만 권장) |
| `coord_ok` | bool | F10 |
| `total_chargers` | int | F06 |
| `available_count` | int | F07 |
| `availability_ratio_observed` | float | F01 |

- 미관측을 `available_count=0` 강제
- `as_of_ts` 이후 status 사용
- mock을 실데이터처럼 `is_mock` 없이 제공
- **parking/traffic mock join 거리를 D1 피처로 넣기** (스키마 검증용 CSV는 `docs/data/`에만 보관)

## 3. D2 — 학습용 패널 (`station_feature_panel`)

### 행 단위
`statId` × `panel_ts` = 1행.

### 기준시각
- `panel_ts`: 수집 틱 시각 (실제 간격은 약 10분대; 이름은 과거 15분 격자 가정에서 옴)
- 공백 안전 패널: 25분 초과 공백 시 이전 상태 폐기 (`build_panel.py` 원칙) → `segment_id` 증가

### 추가 컬럼 (D1 +)
| 컬럼 | 설명 |
|---|---|
| `panel_ts` | 패널 시각 |
| `avail_rate_lag_15m` | **시간 기준** 약 15분 전 `availability_ratio_observed` (아래 정의) |
| `avail_rate_lag_60m` | **시간 기준** 약 60분 전 동일 |
| `segment_id` | 연속 수집 구간 ID · lag는 **같은 segment 안에서만** 조회 |

#### lag 정의 (정본 · 2026-07-31)
행 시프트(`shift(1)`/`shift(4)`)가 **아님**. 실제 시계로 본다.

| 컬럼 | 찾는 틱 T' | 허용창 | 없으면 |
|---|---|---|---|
| `avail_rate_lag_15m` | 같은 `statId`·`segment_id`에서 `T' ≤ panel_ts − 15분`인 최신 틱 | `T' ≥ panel_ts − 27분` (tolerance 12분) | **null** |
| `avail_rate_lag_60m` | 동일, `T' ≤ panel_ts − 60분` | `T' ≥ panel_ts − 75분` (tolerance 15분) | **null** |

- 긴 수집 공백 직후·세그먼트 첫 틱은 lag가 null인 것이 정상 (공백 너머 값 금지).
- 구현: `build_d2_panel.add_avail_rate_time_lags` · 재계산만: `processing/analysis/refresh_d2_avail_lags.py`

원천: SANDBOX status snapshots + `load_snapshots.py`.
