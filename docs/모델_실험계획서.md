## 0. 결론 (모델 선정 문장)

> 대구 EV 세이프차지의 **1차 예측모델**은 표형 데이터·결측·범주형·비선형 관계에 강한 **LightGBM 이진분류**로 선정한다.  
> **Logistic Regression**을 기준모델로, **CatBoost**를 비교모델로 둔다.  
> 타깃은 *예상 도착시각에 해당 충전소에서 호환 충전기 1대 이상 사용 가능 여부* (`available_at_arrival`).  
> **현재**는 규칙 기반 추천을 먼저 구현하고, **5분 간격 status를 최소 4주(권장 8주)** 수집한 뒤 지도학습으로 전환한다.  
> 사용자 선택·도착 성공 로그가 쌓인 뒤에야 **LightGBMRanker**를 검토한다.

## 3. Phase A — 규칙 기반 추천 실험 (지금)

### 3.1 실험 가설

> 상태 미관측을 “사용 불가”로 두지 않고, 가용·신뢰도·위험·편의를 분리 합산하면  
> **설명 가능한 MVP 추천**이 가능하다.

### 3.2 파이프라인

```text
후보 충전소 필터링
  → 도착 예상시간 계산 (TMAP 또는 임시 거리)
  → 현재 충전 가능성 점수
  → 상태정보 신뢰도
  → 교통·주차·운영조건 위험도
  → 최종 추천점수
```

### 3.3 점수식 (시연용 초기값 — 정답 주장 금지)

```text
recommendation_score =
    availability_score * status_reliability
  - eta_penalty
  - charger_shortage_penalty
  - operation_restriction_penalty
  - parking_congestion_penalty
  - traffic_incident_penalty
  + convenience_bonus
```

팀 공통 가중치와의 대응:

| 공통 가중치 | 규칙 항 |
|---|---|
| 충전 가능성 40% | `availability_score` |
| 상태 신뢰도 20% | `status_reliability` |
| 이동시간 15% | `eta_penalty` |
| 대기·충전기 수 15% | `charger_shortage_penalty` |
| 주차·운영·편의 10% | parking / operation / convenience |

### 3.4 UX 상태 표시 (필수)

| 내부 상태 | 사용자 문구 |
|---|---|
| AVAILABLE | 사용 가능: 확인됨 |
| CHARGING 등 | 사용 중/점검: 확인됨 |
| status_missing | **상태 미확인: 실시간 정보 부족** |

### 3.5 Phase A 실험 목록

| ID | 실험 | 입력 | 성공 기준 | 우선순위 |
|---|---|---|---|---|
| A-01 | 후보 필터 (운영중·호환·제한·좌표OK) | `charger_master` | 좌표 이상 27건 제외/경고 | P0 |
| A-02 | 관측분 가용 vs 미관측 분리 점수 | `charger_current_view` | unknown을 0으로 처리하지 않음 | P0 |
| A-03 | `status_age` → 신뢰도 등급 | status | 5/15분 규칙과 정합 | P0 |
| A-04 | 충전소 단위 집계 점수 | A-02~03 | `statId` grain | P0 |
| A-05 | ETA placeholder (직선거리) | lat/lng | TMAP 전까지 mock 명시 | P1 |
| A-06 | 주차·교통 mock 패널티 | parking/traffic mock | `isMock` 표시 | P1 |
| A-07 | POI 보너스 (좌표 있는 164건) | `poi_master` | city_tour 239 공간 제외 | P1 |
| A-08 | 추천 이유 문장 생성 | score breakdown | 설명 가능 3줄 | P0 |

## 4. Phase B — 지도학습 (반복 수집 후)

### 4.1 주 모델

| 역할 | 모델 |
|---|---|
| 기준 | Logistic Regression |
| **최종 후보** | **LightGBM Classifier** |
| 비교 | CatBoost |

비교 순서: `LR → LightGBM → CatBoost`

### 4.2 왜 LightGBM인가

- 표형 공공데이터에 강함  
- 숫자·범주·결측 혼재에 유리  
- 비선형·상호작용 학습 가능  
- FastAPI 서빙·속도에 유리  
- SHAP으로 추천 이유 설명 가능  
- 딥러닝보다 데이터·구현 부담 적음  

### 4.3 타깃

```text
available_at_arrival = 1
  iff (요청시각 + ETA) 시점에 호환 충전기 ≥ 1대가 AVAILABLE
else 0
```

- **상태 미수집 관측은 0으로 넣지 않는다** (학습 제외 또는 별도 결측 관리)  
- 학습 행 grain: **`요청시각 × 사용자 위치 × 후보 충전소`**

### 4.4 충전소 단위를 쓰는 이유

사용자는 충전기 ID가 아니라 **충전소**를 고른다.  
첫 모델은 복잡도 낮은 **충전소 단위 이진분류**를 권장.  
필요 시 충전기 확률 → “최소 1대 가용”으로 합치는 하이브리드는 2차.

### 4.5 피처 우선순위

| 등급 | 피처 |
|---|---|
| **P0** | available/charging/unknown 수, 전체·호환 충전기 수, status_age, ETA, 시각·요일·공휴일, 유형·출력, 운영시간·제한·중지 |
| **P1** | 15/30/60분 가용률, 동일 요일·시간대 과거 가용률, 상태변경 횟수, 평균 충전·대기 지속, 교통속도·혼잡·돌발, 주차점유, 기온·강수 |
| **보너스(예측 본체와 분리)** | 관광지·공원 수, 최근접 편의거리 → **최종 순위 보너스**만 |

### 4.6 평가

| 구분 | 지표 |
|---|---|
| 확률 | PR-AUC, ROC-AUC, Log Loss, Brier, Calibration |
| 보정 | Platt / Isotonic |
| 추천 | Top-1 성공률, Top-3 포함률, P@K, R@K, NDCG, 평균 ETA, 실패율 |

서비스 핵심 KPI:

```text
추천 1순위 충전소에 도착했을 때 실제 충전 가능했던 비율
```

### 4.7 분할

- **시간 분할** (예: 1–6주 train / 7주 val / 8주 test)  
- TimeSeriesSplit / Rolling Window  
- 일부 충전소 hold-out으로 신규 일반화 확인  
- **무작위 row split 금지** (누수)

### 4.8 Phase B 실험 목록

| ID | 실험 | 성공 기준 |
|---|---|---|
| B-01 | 라벨 생성 파이프라인 | 미관측→0 금지, 문서화 |
| B-02 | LR baseline | 보정·PR-AUC 보고 |
| B-03 | LightGBM | LR 대비 실질 개선 |
| B-04 | CatBoost | LR/LGBM과 표 비교 |
| B-05 | 확률 보정 | Brier·calibration curve |
| B-06 | Top-K 시뮬레이션 | Top-1/Top-3 KPI |

## 7. 최종 서빙 구성 (목표)

```text
[1] 후보 필터 (호환·운영·제한·거리)

[5] 출력: 확률 / ETA / 신뢰도 / 추천이유 / 주의(상태 미확인)
```
