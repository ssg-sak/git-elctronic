### 지표 정의 (분석 공통)

| 이름 | 정의 | 주의 |
|---|---|---|
| **가용률** | `availability_ratio_observed` | 관측(usable) 분모. 미관측 제외 |
| **가용확인률** | `has_confirmed_available` 평균 | 충전소×시각 단위 비율 |
| **충전중 비율** | `in_use_count / usable_known` | “비어 있음”의 반대면 |
| **미관측률** | D1 `unobserved_rate` | 패널만으로 전체 마스터 미관측은 과소 |

## 3. 분석별 계획

### E1. 시간대별 가용성

| 항목 | 내용 |
|---|---|
| **질문** | 몇 시에 관측 가용률이 높고, 몇 시에 낮아지는가? |
| **단위** | `panel_ts` → KST `hour` (0–23). 필요 시 3시간 버킷 |
| **집계** | hour별: 가용률 평균·중앙값, 가용확인률, 표본 충전소 수·패널 행 수 |
| **층화** | (선택) `known_chargers` 1대 / 2–4 / 5+ |
| **산출** | 표 + 막대/라인 1장 · `EDA_REPORT` §시간대 |
| **피처 연결** | “피크 시간대에 F01·lag가 더 중요” 문장 → `피처_카탈로그` 메모 |
| **함정** | 야간 수집 공백·segment 경계. 표본 적은 hour는 회색 표시 |

### E2. 요일별 가용성

| 항목 | 내용 |
|---|---|
| **질문** | 평일 vs 주말에 가용 패턴이 다른가? |
| **단위** | `panel_ts` → `weekday` (월=0 … 일=6), 평일/주말 이분 |
| **집계** | 요일별 가용률·가용확인률 · hour×weekday 히트맵(여유 시) |
| **교차** | F08(`is_operating_now`) — “주말 미개방” 문구 비율과 해석만 (인과 단정 금지) |
| **산출** | 표 + (선택) 히트맵 · `EDA_REPORT` §요일 |
| **피처 연결** | 요일 더미/패턴은 ② 후보. ①은 **관찰 근거**만 기록 |
| **함정** | 수집 일수가 짧으면(현재 ~수일) **잠정** 표기. 공휴일 달력 없음 |

### E3. 충전기 수별 가용성

| 항목 | 내용 |
|---|---|
| **질문** | 1대 소는 실패 위험이 큰가? 다대 소는 가용확인이 쉬운가? |
| **단위** | 충전소. `total_chargers` = 마스터 기준 (D1 F06) |
| **버킷** | 1 / 2–3 / 4–6 / 7+ (데이터 보며 조정) |
| **지표** | 버킷별: `unobserved_rate`, `availability_ratio_observed`(관측 있는 소만), `has_confirmed_available` 비율 |
| **데이터** | D1 latest + (선택) D2를 `statId`로 조인해 시간 평균 가용률 |
| **산출** | 교차표 · `EDA_REPORT` §규모 |
| **피처 연결** | F06·F02·F03이 왜 같이 가는지 근거 |
| **함정** | 패널 `known_chargers` ≠ 마스터 전체 대수. 혼용 시 명시 |

### E4. 최신성(status age)별 가용성

| 항목 | 내용 |
|---|---|
| **질문** | 정보가 오래될수록 “가용”을 믿기 어려워지는가? 관측 가용과 age는 어떻게 같이 보이나? |
| **단위** | D1 충전소 또는 충전기급 age → 충전소 min age (F04) |
| **버킷** | AGENTS와 동일: ≤5분 / 5–15분 / >15분 (+ 미관측 별도) |
| **지표** | 등급별 행 수, 가용확인률, 가용률 분포 |
| **데이터** | D1 `status_age_minutes`, `reliability_grade` · 필요 시 snapshots에서 `as_of - statUpdDt` 검증 |
| **산출** | 표 · `EDA_REPORT` §최신성 |
| **피처 연결** | F04·F05가 F01과 **같이** 쓰여야 하는 이유 (신선도 없는 가용은 위험) |
| **함정** | age와 가용의 **상관 ≠ 인과**. “오래됨 → 비어 있음”으로 쓰지 말 것 |

### E5. D2 패널 활용 (방법·품질)

| 항목 | 내용 |
|---|---|
| **질문** | 패널이 E1–E4를 지탱하기에 충분한가? |
| **점검** | 구간(`segment_id`) 수, `panel_ts` 범위, 충전소 커버, 결측 lag 비율, gap-safe 25분 정책 재확인 |
| **산출** | `EDA_REPORT` §데이터 절에 “패널 메타” 표 (행수·기간·제한) |
| **후속** | 분석 전에 `build_d2_panel.py` 재실행 → 경로를 계획서/보고에 고정 |

## 4. 실행 순서 (권장)

```text
0. D2 패널 재생성 (최신 snapshots 반영)
1. E5 패널 품질·기간 요약          ← 반나절
2. E1 시간대 + E2 요일             ← 1일
3. E3 충전기 수 × 가용             ← 반나절
4. E4 최신성 × 가용                ← 반나절
5. EDA_REPORT 보완 절 작성
6. 피처_카탈로그 §1에 “근거 수치” 한 줄씩 보강
7. (선택) ②에게 관찰 요약 공유 — 점수는 요청하지 않음
```

스크립트 위치 (구현 시):

```text
apps/data-pipeline/evaluation/personal/experiments/
  또는 evaluation/eda/
    eda_panel_availability.py   # E1–E5 집계 → CSV/표
```

산출물:

| 산출 | 경로 |
|---|---|
| 집계 CSV | `evaluation/results/eda/` (신규) |
| 보고서 보완 | `docs/보고/EDA_보고서.md` (섹션 추가, 7/16 본문 유지) |
| 피처 근거 | `docs/data/스키마/피처_카탈로그.md` §1 갱신 |
| 본 계획 | `docs/보고/EDA_계획_상태패널.md` (이 파일) |

## 5. 해석 규칙 (보고서 문장 가이드)

| 해도 됨 | 하면 안 됨 |
|---|---|
| “월~수 기준 hour=18 가용률 평균이 낮다 (표본 N=…)” | “저녁에 가면 실패한다” (단정) |
| “1대 소는 가용확인률이 낮다” | “1대 소는 추천 제외” (정책=②) |
| “age>15분이면 가용 해석에 주의” | “age만으로 점수 −20점” (가중치=②) |
| “패널 기간이 짧아 요일 패턴은 잠정” | “주말 패턴 확정” |

미관측·mock·ETA null 정책은 [`학습가이드_관측과가용.md`](../data/가이드/학습가이드_관측과가용.md) · `데이터셋_명세`을 따른다.
