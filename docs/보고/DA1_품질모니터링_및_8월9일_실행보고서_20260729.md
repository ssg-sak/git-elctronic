## 1. 요약

현재 DA① 데이터는 모델 실험과 추천 입력 검증을 진행할 수 있는 상태다. 최신 loop1 검증은 `PASS 6 / WARN 1 / FAIL 0`이며, 정제 후 grain 중복은 0건이다.

현재 원본 WARN은 API 페이지 경계에서 생긴 중복으로 확인됐다. 상태값이 실제로 충돌한 그룹은 6개뿐이며, 최신 `statUpdDt` 선택 규칙으로 결정적으로 정제된다.

새로 추가한 모니터링 결과의 전체 상태는 `WARN`이다. 원인은 중복이나 수집 간격이 아니라 최신 로컬 스냅샷이 약 150분 전인 최신성 경고다. 따라서 추천 입력 데이터는 전달 가능하지만, 현재 상태 데이터로 실시간 화면을 판단해서는 안 된다.

## 3. 원본 중복 WARN 분석

원본 중복 1,346개 그룹 중 상태값까지 달랐던 그룹은 다음 6개다.

| 스냅샷 | 충전소/충전기 | 페이지 | 상태 변화 | 시각 차이 |
|---|---|---|---|---:|
| 2026-07-19 17:31:25 | PI000129 / 01 | 4 → 5 | 2 → 3 | 424초 |
| 2026-07-23 10:36:17 | JA270010 / 01 | 4 → 5 | 5 → 2 | 295초 |
| 2026-07-23 10:36:17 | JA270010 / 02 | 4 → 5 | 5 → 3 | 295초 |
| 2026-07-23 16:26:24 | HE000883 / 24 | 3 → 4 | 3 → 2 | 120초 |
| 2026-07-25 20:04:27 | LU101196 / 01 | 4 → 5 | 3 → 2 | 7초 |
| 2026-07-28 14:21:16 | LU001249 / 01 | 3 → 4 | 3 → 2 | 26초 |

모든 충돌은 같은 스냅샷의 서로 다른 페이지에서 발생했으며, `fetchedAt`은 동일했다. 따라서 API 페이지 조회 중 상태가 갱신되거나 페이지 결과가 일관되지 않았을 가능성이 높다. 원본을 삭제하지 않고 다음 규칙으로 정제한다.

1. 키는 `snapshotId × statId × chgerId`로 고정한다.
2. `statUpdDt`가 가장 최신인 행을 선택한다.
3. `statUpdDt`가 같으면 `pageNo`, 원본 행 순서로 tie-break한다.
4. 정제 후 중복이 남으면 DA② 핸드오프를 차단한다.

| horizon | 라벨 행 | 양성률 |
|---:|---:|---:|

판정:

- 5분 horizon은 10분 수집 주기와 겹치는 경우가 많아 독립적인 목표로 보기 어렵다.
- 5분 데이터를 즉시 삭제하지는 않는다.
- MVP 비교는 10·15·30분을 우선 후보로 둔다.
- 최종 horizon 선택은 DA②의 시간 외 평가와 ablation 결과로 결정한다.

### 클래스 불균형

양성률이 92% 이상이므로 Accuracy를 주 지표로 사용하면 안 된다. DA②에는 PR-AUC, Brier, LogLoss, 음성 Recall, calibration, class weighting 비교를 전달한다.

### 희소 피처

과거 이용 이력 피처는 관측률이 약 7.27%이므로 기본 모델 입력에서 보류한다. 결측을 0으로 채워 정보가 있는 것처럼 만들지 않는다.
