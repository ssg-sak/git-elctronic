## 1. 한 줄 결론

**원본에는 실시간 API 페이지 경계 이동으로 인한 중복이 있었지만, 최신 `statUpdDt`를 선택하는 정제 규칙을 적용한 결과 추천 입력 키 중복은 0건이며 시간 역전과 미래정보 누출도 발견되지 않았다.**

이 판정은 추천 입력 데이터의 정합성에 대한 것이다. 현재 가용한 충전기가 사용자의 도착 시점까지 비어 있음을 보장하지 않는다.

## 4. 중복 원인과 정제 규칙

중복은 같은 스냅샷 파일에서 동일 충전기가 인접한 API 페이지에 다시 나타나는 형태였다.

```text
같은 snapshotId·같은 fetchedAt
pageNo 4: 이전 상태
pageNo 5: 더 최근 statUpdDt 상태
```

실시간 API 페이지를 순차 조회하는 동안 상태가 변경되거나 정렬 순서가 바뀌면 레코드가 페이지 경계를 이동할 수 있다. 실제로 상태 값까지 서로 다른 중복 그룹이 6개 확인되었다.

정제 규칙:

1. 키를 `snapshotId × statId × chgerId`로 고정한다.
2. 중복 키에서는 `statUpdDt`가 가장 최신인 행을 선택한다.
3. `statUpdDt`가 같으면 `pageNo`, 원본 행 순서로 결정한다.
4. 정제 후 키 중복이 남으면 품질 게이트를 실패 처리한다.

수집 원본은 수정하지 않고, DA①의 추천 입력 전처리에서만 이 규칙을 적용한다.

## 5. SOC 입력 검증

`EtaSocCalculator`에 다음 방어 규칙을 반영했다.

- 차량 마스터 등록 차종은 실제 배터리 용량·주행거리 사용
- 미등록 차종은 50kWh·4.0km/kWh fallback 사용
- SOC 입력은 0~100만 허용
- 음수 거리·무한대·NaN 입력 거부
- SOC 10% 이하를 위험 구간으로 통일
- 도달 불가와 화면 표시용 0%를 구분

검증 결과:

```text
SOC 계산 테스트 11개 통과
상태 as-of 및 페이지 경계 중복 테스트 4개 통과
```

## 6. DA② 핸드오프 가능 범위

현재 넘길 수 있는 것:

- 기준시각이 명확한 상태 이력
- 정제 후 충전기 1개·스냅샷 1개당 1행
- 상태 이벤트 시각과 수집 시각의 분리
- 차량별 도착 SOC 보수적 기준선
- 미등록 차량 fallback 여부

아직 넘기면 안 되는 주장:

- 충전 성공 보장
- 현재 가용 상태가 도착 시점까지 유지된다는 주장
- 단일 BMS 트립으로 전체 차종 SOC 정확도를 검증했다는 주장
