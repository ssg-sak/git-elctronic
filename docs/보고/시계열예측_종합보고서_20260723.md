## 0. 한 줄 결론

**변경분 status로 ETA 15분 “실관측” 라벨·시간순 베이스라인은 이미 성립한다.**  
병목은 “라벨 개수”가 아니라 **캘린더 일수·수집 간격·야간 공백**이었다.  
PC 15·10분 수집으로 6일·median 15분 구간을 쌓아 게이트에서 **CONDITIONAL GO**를 냈고,  
그날(7/22)부터 **interval 5분 + Lightsail systemd**로 옮겨 **야간 연속·gap≈5분**을 입증했다.  
당분간은 **규칙 MVP + 일별이용 보조**를 유지하고, **연속 14일(5분)** 쌓인 뒤 게이트를 다시 연다.

## 2. 왜 시계열이 필요한가 (문제 정의)

| 잘못된 가정 | 올바른 프레임 |
|---|---|
| 지금 비어 있으면 도착해도 비어 있다 | **현재 상태 ≠ 도착 시점 예측** |
| 미관측 = 사용불가 / null = 0 | **미관측 ≠ 사용불가**, **null ≠ 0** |
| 일별 이용량으로 ETA 라벨 | 일별 이용은 **보조 혼잡 피처만** |
| 행평균 가용률 = 플릿 진실 | 변경분 피드는 바쁜 기기 과다 → **패널(1대=1표)** 필요 |

제품 목표: “가장 가까운 곳”이 아니라 **ETA에 실제로 쓸 수 있을 곳**.  
DA➀은 점수 UI의 “확률 xx%”를 주장하지 않고, **관측·라벨·수집 품질**을 판정한다.

## 4. Phase A — PC 15·10분 수집으로 쌓인 것

### 4.1 수집 품질 (게이트 EXP-011, ~07-22 시점)

| 지표 | 값 | 의미 |
|---|---|---|
| 틱 수 / 캘린더 | **342** / **6일** | 라벨은 많으나 **일수 부족** |
| gap median / mean / max | **15.0** / 22.3 / **672분** | 설계 5분과 불일치 · 야간 대공백 |
| ≤5.5분 준수율 | **3.2%** | GO 확정 불가의 주원인 |
| ≤15.5분 | 97.4% | “15분급”으로는 거의 연속 |
| API 성공률 | 100% | 실패가 아니라 **스케줄·PC OFF** 문제 |
| 관측 충전기 / 소 | 16,931 / 3,421 | 변경분으로 누적 커버 확대 |
| 이벤트 행(dedup) | 166,336 | |

**유지 vs 실패:** 틱 성공/실패는 `index`·`call_log`로 구분 가능.  
충전기 단위 “유지” vs “미관측”은 period 창 한계로 **부분적**.  
`polled OK + unchanged` 명시 행 없음 → 4층 설계로 보완.

### 4.2 초기 검증 (EXP-019, 07-18)

- 스냅샷 83개 무결성 통과, 간격 중앙값 15분.
- 누적 관측 충전기 493 → **10,672** (부분 관측이어도 누적은 넓어짐).
- **야간 PC OFF ≈ 9.7시간 공백** → “노트북 수집 = 시계열 구멍”을 조기 확정.

### 4.3 패널 복원 (EXP-013)

| 지표 | 값 |
|---|---|
| ticks × chargers | 342 × 16,931 |
| observed / imputed / null | **2.82% / 2.10% / 95.08%** |
| 규칙 | 실제 수집 틱만 · age≤25분 ffill · 빈 5분 격자 생성 안 함 |

null이 큰 것은 실패가 아니라 **변경분 피드** 특성이다.

### 4.4 ETA 15분 실관측 타깃 (EXP-014)

정의: t에서 horizon±7.5분 창에 **실관측**으로만 1/0, 없으면 **null**(0 금지).

| horizon | 라벨 행 | 커버리지 | 양성비율 | 일수 |
|---|---:|---:|---:|---:|
| 5분 | 117,955 | 11.2% | 65.9% | 6 |
| 10분 | 114,476 | 10.9% | 65.8% | 6 |
| **15분** | **114,118** | **10.8%** | **65.8%** | **6** |
| 30분 | 107,899 | 10.2% | 65.7% | 6 |

- 시간순 분할 가능: train 17–19 / valid 20 / test 21–22.
- **편향:** 자주 바뀌는 소·충전기가 라벨에 과대 대표.

### 4.5 일별 이용 EDA (EXP-012 · 20260722)

- 전체 128,263 · 2025년 87,573 · 시 소 219 중 EvCharger 매칭 201.
- 평일/주말·급완속·rolling 피처 가능.
- **ETA 직접 타깃 금지.**

### 4.6 시간순 백테스트 (라벨 서브셋)

| 모델 | Brier↓ | LogLoss↓ | PR-AUC |
|---|---:|---:|---:|
| persistence | 0.344 | 4.75 | 0.803 |
| 소×요일×시간 과거 가용 | 0.221 | 0.633 | 0.672 |
| Logistic | 0.174 | 0.514 | 0.884 |
| **GradientBoosting** | **0.172** | **0.508** | **0.885** |

**해석 주의:** 6일·변경분 편향·양성 66% → Hit@5·점수를 제품 “확률”로 쓰면 안 됨.  
ML이 persistence보다 낫다는 **힌트**일 뿐, GO 확정이 아님.

### 5.1 Lightsail 첫 야간 구간 (pull 2026-07-23)

상세: [`docs/보고/Lightsail_가용률보고_20260723.md`](./Lightsail_가용률보고_20260723.md)  
로컬 복사: `docs/data/loops/_archive/from_lightsail_20260723/`

| 지표 | PC 게이트 구간 | **Lightsail 야간(~10.7h)** |
|---|---|---|
| interval 설계 | 5분 (미준수) | **5분** |
| gap median | **15.0분** | **5.02분** |
| 25분+ 공백 | 다수(야간 대공백) | **0회** |

→ **“PC OFF = 시계열 구멍” 문제는 서버 이전으로 구조적으로 해소.**  
아직 **14일 캘린더**는 미충족 → 판정은 CONDITIONAL GO 유지, 조건 이행 중.

### 5.2 패널 가용률 (Lightsail 야간)

정의: `stat=2 / (stat=2+3)` · forward-fill 패널(1대=1표).

| 방식 | 가용률 |
|---|---:|
| **패널(권장)** | **45.7%** |
| raw 행가중 | 79.9% (과대 편향) |
| 범위 | 33.8% ~ 75.3% |

| 구간 | 평균 |
|---|---:|
| 야간(23–06) | 42.5% |
| 주간(07–22, 아침 일부) | 55.2% |
| 8시 전후 | ~74% |

해석: 야간 **충전중↑ → 가용↓**, 아침 **해제 → 가용↑** 패턴이 패널에 나타남.  
raw 79.9%를 쓰면 현실을 왜곡하므로 **리포트·MVP는 패널 값**.

### 5.3 소통(loop3) 동시 적재

- 15분 · linkspeed ≈1960 · 평균속도 ~39.7 km/h · incident ~1.2건/틱.
- 링크 좌표 부재 → 충전소 공간조인은 후속.

## 6. 예측(시계열) 관점에서의 현재 상태

```text
[가능]  ETA15 실관측 라벨 생성
[가능]  시간순 train/valid/test · persistence / 요일시간 / Logistic / GBDT
[가능]  패널 가용률·status_age·관측 여부 피처
[가능]  일별이용 weekday·MA 보조 피처
[진행]  5분·24h 연속 수집 (Lightsail)
[미완]  라벨 캘린더 ≥14일 (주간 포함)
[미완]  status_event 파생 파이프 (4층 L3)
[미완]  소통 링크맵 ↔ 충전소 조인
[금지]  null→0 · 미관측→사용불가 · mock 주차로 성능 주장 · ML점수=확률 UI
```

### 재게이트 체크리스트 (GO 승격 후보)

1. Lightsail status **연속 ≥14일** (야간 포함, gap median ≤6분대 유지)
2. ETA15 라벨 재생성 + 시간순 백테스트 재실행
3. persistence 대비 Brier/PR **일관 개선**이 **복수 주**에서 반복되는지
4. (권장) 주기 full refresh로 커버리지 상향 · `unchanged` 로그 도입

## 9. 종합 판정 문구 (팀 공유용)

> **CONDITIONAL GO — 이행 중.**  
> 15·10분 PC 수집으로 ETA 15분 실관측 타깃·시간순 베이스라인의 **구조적 가능성**을 입증했고(6일·median 15분),  
> 동일 주 Lightsail 5분 전환으로 **야간 연속·설계 간격 준수**를 열었다.  
> ML로 핵심 목표를 “입증 완료”했다고 보지 않는다.  
> **규칙 기반 MVP를 유지**한 채 5분 status를 **14일** 쌓은 뒤 게이트를 다시 연다.

```
DA➀ | timeseries prediction synthesis | 2026-07-23
PC 15·10분 → gate CONDITIONAL GO → Lightsail 5분 24h
```
