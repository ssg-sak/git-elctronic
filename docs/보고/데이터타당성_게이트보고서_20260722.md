## 0. 한 줄 결론

**ETA 15분 “실관측” 타깃은 만들 수 있고, 시간순 베이스라인 비교도 돌아간다.**  
그러나 수집이 설계(5분)와 어긋나고(실제 median **15분**), 라벨 캘린더가 **6일**뿐이라 **ML로 핵심 목표를 입증했다고 보기엔 이르다.**  
프로젝트는 **유지**하되, 당분간은 **규칙 기반 MVP + 일별 이용 보조 피처**로 가고, status를 **5분·연속**으로 쌓은 뒤 게이트를 다시 연다.

## 1. 검증 목적과 원칙

### 1.1 목적

기능 추가가 아니라 **데이터로 핵심 목표가 성립하는지** 판정하는 게이트다. 등급은 아래 셋 중 하나다.

| 등급 | 의미 |
|---|---|
| **GO** | ETA 15분 관측 타깃·시간순 검증·누출 없는 베이스라인 비교로 MVP 수준 입증 가능 |
| **CONDITIONAL GO** | 구조는 되나 기간·커버·수집 품질 부족. 일정 내 축적 가능. 그동안 규칙 MVP 유지 |
| **NO-GO** | 구조적으로 타깃 불가, 유지/실패 구분 불가, ID 연결 불능 등 — 일정 내 회복 어려움 |

### 1.2 적용한 원칙

- 상태 **5분 수집**이 설계이나, 실제 운영 간격을 측정해 판정에 반영
- 변경 없으면 이벤트 중복 저장 없이 lastSeenAt만 갱신 가능 → **이력 소실 여부** 검증
- 학습 시 이벤트를 패널로 재구성하되, **미관측 ≠ 사용불가**, **null ≠ 0**
- **현재 상태 ≠ 도착 시점 예측**
- 실데이터 / mock 분리 (주차 mock은 성능 평가 제외)
- 검증되지 않은 점수를 **확률**로 표현하지 않음
- 규칙 기반은 ML 실패 시 **폴백**
- **2025년 전후 일별 이용(~9만 행대)** 은 ETA 직접 타깃이 아님 (보조 혼잡 피처만)

## 7. 시계열 백테스트 (시간순)

조건: ETA15 라벨 ≥500건 → 본 데이터는 **114,118**로 실행.  
랜덤 split **금지**. train/valid/test = **날짜 순**.  
JSON: `json/backtest.json` · 표: `tables/backtest_metrics.csv` · 그림: `figures/calibration_eta15.png`

### 7.1 분할

| 분할 | 날짜 | 행 수 |
|---|---|---:|
| train | 07-17 ~ 07-19 | 52,292 |
| valid | 07-20 | 20,315 |
| test | 07-21 ~ 07-22 | **41,511** |

피처는 **시각 t 이전·현재 관측만** (available_observed_at_t, observed_chargers_at_t, hour, weekday).  
타깃에 재구성만 사용하지 않음. null을 0으로 넣지 않음.

### 7.2 결과 (test, 라벨 서브셋)

| 모델 | Brier ↓ | LogLoss ↓ | Precision | Recall | PR-AUC | Hit@5 |
|---|---:|---:|---:|---:|---:|---:|
| 현재상태 유지 (persistence) | 0.344 | 4.75 | 0.916 | 0.537 | 0.803 | 0.992 |
| 소×요일×시간 과거 가용률 | 0.221 | 0.633 | 0.672 | 1.000 | 0.672 | 0.984 |
| 규칙 프록시 (=persistence) | 0.344 | 4.75 | 0.916 | 0.537 | 0.803 | 0.992 |
| Logistic Regression | 0.174 | 0.514 | 0.745 | 0.883 | 0.884 | 1.000 |
| sklearn GradientBoosting | **0.172** | **0.508** | 0.738 | 0.904 | **0.885** | 1.000 |

LightGBM/XGBoost는 환경에 없어 GBDT로 대체. LSTM/딥러닝 미사용.

### 7.3 해석 주의 (과대 해석 금지)

1. 점수는 **라벨된 행만**의 모델 점수이며, 제품에 “확률 xx%”로 쓰면 안 된다.  
2. 변경분 편향 + 양성 66% → Hit@5가 낙관적으로 보일 수 있다.  
3. 캘린더 **6일**만으로 walk-forward를 “검증 완료”로 보면 안 된다.  
4. ML이 persistence보다 Brier는 개선되나, **데이터 부족·편향**과 섞여 있을 수 있다.  
5. 기존 규칙 점수의 별도 ETA 캘리브레이션 파일은 없어, 규칙 프록시는 persistence와 동일하게 둠.

### 8.1 등급: **CONDITIONAL GO**

| 항목 | 내용 |
|---|---|
| **판정** | CONDITIONAL GO |
| **핵심 목표 유지** | 가능 (당분간 확률 주장 금지) |
| **일정 내 보완** | 가능 |
| **필요 최소 수집** | **14일** (연속·주간 포함). 라벨 수(>5만~11만)는 이미 충분 — 병목은 **일수·5분 준수·커버리지** |

### 8.2 핵심 근거 5개

1. status **342틱**, gap median **15분**, 5분 준수율 **3.2%**  
2. 패널 observed/imputed/null = **2.8% / 2.1% / 95.1%** (변경분 정상 반영)  
3. ETA15 **실관측 라벨 114,118**, 커버리지 **10.8%**, **6일**, 양성 **65.8%**  
4. 일별 이용 **128,263**(2025=87,573) → **보조만**, ETA 타깃 아님  
5. 시간순 백테스트 가동(GBDT Brier 0.172 vs persist 0.344) — 단 일수·편향 제한

### 8.3 치명적 문제

- 틱 미반환 ≠ 사용불가; 타깃은 **실관측만**
- 수집이 설계 5분이 아님
- `unchanged` 확인 행 부재 → collection_log + event + serving 분리 필수

### 8.4 수정 가능한 문제

- loop1 interval을 **5분**으로 고정, 야간 공백 최소화  
- 라벨 캘린더 **≥14일** 후 ML 게이트 재실행  
- 주기적 full status refresh로 커버리지 개선  
- 일별 이용은 join 후 보조 피처만

### 8.5 목표 축소 시 대체 문구

> 도착 시 사용 가능성을 확률로 보장하기보다, **실시간 관측 가용·신뢰도·과거 일별 이용량 보조 피처**로 규칙 기반 추천 MVP를 유지하고, status를 5분·연속 수집해 ETA 타깃을 축적한다.

### 8.6 권고 액션

1. **지금:** 규칙 기반 MVP + 이용량 보조 피처, ML 점수를 확률 UI에 넣지 말 것
