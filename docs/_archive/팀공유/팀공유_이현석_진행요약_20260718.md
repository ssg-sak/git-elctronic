## 1. 한눈에

```text
운전자: "지금 충전하러 갈 건데, 어디로 가지?"

기존 방식 : 제일 가까운 곳 → 갔더니 다 차 있거나 고장
우리 목표 : 가면 실제로 충전할 수 있을 곳
```

역할 분담 (AI·데이터):

```text
① 데이터·파이프라인 (이현석) : 정의·품질·전처리·특성·데이터셋·status 시계열
② 모델·평가·서빙 (상대)     : 점수·위험도·추천 이유·ML·평가·추론
```

진행 상태 (①):

```text
[완료] 전처리·품질 baseline
[지금] 충전소 상태 15분 기록 계속 모으기
[다음] 데이터 사전·공간결합·피처 정의서 · ②에 입력 테이블 핸드오프
```

---

## 2. 지금 상황 (①)

### 하고 있는 것
충전소 **실시간 상태**를 15분마다 쌓고, 결측·공백·한도를 자동 점검합니다.  
한 번 찍은 스냅샷만으로는 “도착했을 때 비는지”를 말할 수 없어서, **시계열 재료**를 먼저 모읍니다.

### 하지 않는 것
추천 점수·Top-N·추천 이유 문장·LightGBM 등 — **② 담당**.

---

## 3. status 수집이 왜 필요한가

- API는 전체 목록이 아니라 **최근 변경분**만 줌 → 한 장은 커버리지가 낮음
- 미관측을 사용 불가로 치면 데이터셋이 틀어짐
- 쌓인 뒤 ①이 특성·데이터셋을 만들고, ②가 점수·모델을 붙임
