## 1. 표준 파이프라인 관점 (현실 → 결론)

교과서 흐름과 **우리 프로젝트가 어디에 해당하는지**를 같은 그림으로 본다.

```text
현실 세계          대구 EV 충전소·충전기·날씨·교통·POI
      ↓
데이터 수집        getChargerInfo/Status · 기상청 · UTIC · (주차 mock)
      ↓
Raw Data           extracted/*.csv · SANDBOX snapshots/ · collection raw XML
      ↓
┌─────────────────────────────────────────────────────────────┐
│                    데이터 전처리                              │
│  자료형      statId/chgerId string · lat/lng float            │
│  결측치      statNm·output·useTime — 정책으로 **유지/플래그**   │
│  중복        snapshot 페이지 경계 dedup · (snapshotId,key)    │
│  이상치      좌표 bbox 밖 27건 → quarantine (삭제 아님)         │
│  문자열      Tour mojibake 복구 · Y/N 그대로                  │
│  날짜/시간   statUpdDt 파싱 · fetchedAt KST · as_of 누수 방지  │
│  범주형      stat 1~9 → 표준 5값 · chgerType 코드표           │
│  데이터 결합 info↔status 조인 · spatial · usage_level         │
│  단위/스케일  kW 문자열 유지 · 거리 m · age minutes           │
│  오류값      invalid stat · API resultCode ≠ 00 → 로그/중단   │
│  파생변수    F01~F18 · reliability_grade · segment_id         │
│  품질 검증   daily_checkpoint · KPI · validate_collection     │
└─────────────────────────────────────────────────────────────┘
      ↓
Clean Data         processed/charger_master · D1 · D2  (← “완벽”이 아니라 **쓸 수 있게 정의됨**)
      ↓
EDA / 분석 / ML    E1~E4 · GO/NO-GO · (② 규칙/ML 점수)
      ↓
결론               “언제·어디·몇 대·얼마나 신선할 때 가용한가” → 추천 입력 근거
```

### 1.1 단계별 우리 매핑

| 표준 단계 | EV SafeCharge에서 뭐냐 | 산출물 |
|---|---|---|
| **현실 세계** | 사용자가 도착했을 때 **꽂을 수 있는지** | (문제 정의) |
| **데이터 수집** | `collection/` · SANDBOX `run_loop` | snapshots, extracted/daily |
| **Raw Data** | API가 준 그대로 CSV/XML | 수정·덮어쓰기 **금지** (정본) |
| **전처리** | SANDBOX preprocess + `processing/` | processed/, quarantine/ |
| **Clean Data** | master + as-of join 결과 | `charger_master`, D1, D2 |
| **EDA/ML** | `evaluation/eda`, ② scoring | EDA_REPORT, (모델은 후속) |
| **결론** | MVP: **규칙 기반 추천** 근거 | KPI, 피처 카탈로그, 핸드오프 |

> **Clean Data ≠ 결측 0.**  
> status **미관측(~97%)**은 “버그 결측”이 아니라 **API가 변경분만 주는 구조**다.  
> 전처리는 **0으로 채우지 않고** `NO_STATUS_OBSERVED` · `unobserved_rate`로 **명시**한다.

### 1.2 전처리 12항목 × 우리 프로젝트

| # | 항목 | 우리에서 하는 일 | 대표 코드/문서 | 주의 |
|---:|---|---|---|---|
| 1 | **자료형** | ID는 string, 좌표·age는 numeric | `load_snapshots`, `cleansing.py` | stat `"2"` ≠ int 2 혼용 금지 |
| 2 | **결측치** | impute 최소화 · 플래그 | [전처리_전후 §2.2](./전후.md) | status **없음 ≠ NaN→0** |
| 3 | **중복** | 틱 내 `(statId,chgerId)` · 패널 `(snapshotId,key)` | `load_snapshots.py` | 페이지 경계 중복 |
| 4 | **이상치** | 좌표 bbox · invalid stat | `quarantine/`, `coordinate_quality_flag` | 삭제 대신 격리 |
| 5 | **문자열** | Tour UTF-8 복구 · trim | `clean_poi.py` | statNm status에서 비어 있음 → info 조인 |
| 6 | **날짜/시간** | `statUpdDt` 14자리 · `as_of_ts` | `status_as_of.py` | **fetchedAt ≠ statUpdDt** |
| 7 | **범주형** | stat→AVAILABLE 등 · chgerType | [상태코드_매핑](../data/스키마/상태코드_매핑.md) | 1,9는 UNKNOWN (고장 아님) |
| 8 | **데이터 결합** | info+status · spatial · usage | `build_d1_snapshot.py` | 키: `statId+chgerId` |
| 9 | **단위/스케일** | kW 문자열, m, minutes, % | 피처 카탈로그 | output 평균 대체 안 함 |
| 10 | **오류값** | API 실패·resultCode·quota | `call_log.jsonl`, quota JSON | 한도 근접 시 skip |
| 11 | **파생변수** | F01 가용률 · F04 age · F05 등급 · lag | `station_features.py`, D2 | 점수(가중치)는 ② |
| 12 | **품질 검증** | 일일 점검 · KPI 10항 · join 검증 | `daily_checkpoint`, `report_kpi` | healthy ≠ “전부 관측” |

### 1.3 Raw vs Clean — 경계선

| | Raw | Clean (우리 정의) |
|---|---|---|
| **정의** | API/수집기 출력 그대로 | 분석·추천에 **규칙이 정해진** 테이블 |
| **예** | `daegu_charger_status_154033.csv` | `station_feature_panel_latest.parquet` |
| **수정** | immutable | 버전·`as_of_ts`·`schema_version` 붙임 |
| **결측** | 그대로 두거나 API 특성 | **의미 부여** (미관측/UNKNOWN/ null+source) |

**중간층** (Raw와 Clean 사이):

```text
processed/charger_master.csv     ← 정적 정제
processed/charger_status_current ← 단발 시점 view (7/16)
status as-of join 결과             ← 동적 + master
```

D1/D2는 **Clean Data의 정본**. EDA는 주로 **D2**, 규칙 추천 입력은 **D1**.

### 1.4 EDA / ML / 결론 — 역할 나눔

| 단계 | ① (우리) | ② (모델·점수) |
|---|---|---|
| **EDA** | E1~E4 패턴·가용·신선도 **관찰** | 가중치·Top-N **안 정함** |
| **통계** | 충전소×시각 집계 · KPI | — |
| **ML** | D2 **입력 테이블** 제공 | 라벨·학습·Serving |
| **결론** | “데이터로 **뭘 말할 수 있는지**” | “**몇 점** 줄지” |

**지금 결론까지 갈 수 있는 것 (라벨 없이):**

- 시간대·규모·신선도에 따른 **가용 패턴** (잠정)
- 1대 소·미관측·age>15m → **해석 주의** 구간
- GO/NO-GO: status 시계열 **프로젝트 유지**, ML 예측은 **후속**

**아직 결론 못 내리는 것:**

- “도착하면 90% 성공” (도착 라벨 D3 미확정)
- mock 주차/교통 기반 **실성능** 주장

## 2. 전체 흐름 (5단 · 프로젝트 내부)

```text
[1] 수집 (raw)          info 1일 1회 · status 10분마다
        ↓
[2] 정제 (clean)        타입·코드·결측 정책 · 격리(quarantine)
        ↓
[3] 마스터 (master)     charger_master = info 정본
        ↓
[4] 상태 결합 (as-of)   status 스냅샷 → 기준시각 이전 최신값
        ↓
[5] 데이터셋 (D1/D2)    충전소 피처 스냅샷 · 시계열 패널
```

| 단계 | 산출 | 지금 상태 |
|---|---|---|
| 1 수집 | snapshots/, extracted/daily/ | ✅ status 루프 7/17~ · info daily 구조 추가 |
| 2 정제 | processed/, quarantine/ | ✅ 7/16 SANDBOX 1회 완료 (정적 소스) |
| 3 마스터 | `charger_master.csv` | ✅ ~25k행 · info 갱신 시 **재빌드 필요** |
| 4 as-of | status join + age/reliability | ✅ `status_as_of.py` · D1에 반영 |
| 5 D1/D2 | parquet/csv latest | ✅ 있음 · **스냅샷 늘 때마다 재생성** |

## 3. 소스별 전처리 (뭘 할지)

### 3.1 충전기 info (정적) — **P-info**

| 항목 | 내용 |
|---|---|
| **입력** | `docs/data/extracted/daily/YYYY-MM-DD/daegu_charger_info_*.csv` |
| **키** | `statId` + `chgerId` |

| **산출** | `charger_master.csv` · 좌표 이상 → `quarantine/` |
| **주기** | info **주 1~2회** 갱신 시 `run_pipeline.py` 재실행 |

### 3.2 충전기 status (동적) — **P-status** ← **지금 핵심**

| 항목 | 내용 |
|---|---|
| **입력 (정본)** | SANDBOX `data/snapshots/daegu_charger_status_*.csv` |
| **입력 (편의)** | `data/daily/YYYY-MM-DD/*_daily.csv` (통합본, API 안 씀) |
| **키** | `statId` + `chgerId` + `snapshotId`(시각) |
| **한다** | 틱별 dedup · `stat` 숫자→표준 5값 · `statUpdDt` 파싱 · `statNm` info 조인 |
| **안 한다** | 미관측 = 고장/0대 처리 · flat extracted status를 D1에 섞기 |
| **산출** | as-of join 입력 · D2 gap-safe 패널 |

**규칙 (반드시)**

| 상황 | 처리 |
|---|---|
| status 행 **없음** | `NO_STATUS_OBSERVED` · 가용 0 **아님** |
| `stat=2` | 사용 가능 |
| `stat=3` | 사용 중 |
| `stat=1,9` | 미확인 (고장 카운트 X) |
| `fetchedAt` vs `statUpdDt` | 신뢰도(F04/F05)는 **statUpdDt** 기준 |

**코드:** `load_snapshots.py` · `status_as_of.py` · `cleansing.py` · `build_d2_panel.py`

## 5. 실행 순서 (일상 루틴)

### 매일 (루프 돌아가면 자동)

```text
1. status 스냅샷 저장          run_loop.py
2. info 1회 (없으면)           ev_charger_info → daily/
3. 전날 status 통합 CSV        daily_export (checkpoint)
4. 전날 일일 점검              daily_checkpoint
```

### 수동 (필요할 때)

```text
A. info master 갱신
   python .../SANDBOX_20260716_preprocess_pipeline/.../run_pipeline.py

B. D1 최신화
   python .../build_d1_snapshot.py

C. D2 최신화
   python .../build_d2_panel.py

D. KPI 보고
   python apps/data-pipeline/processing/analysis/report_kpi.py
```

**권장 주기 (MVP)**

| 작업 | 주기 |
|---|---|
| D1 rebuild | **1~2일** (status 쌓일 때) |
| D2 rebuild | **주 1회** 또는 EDA 전 |
| info master | **주 1~2회** |
| POI/날씨 | **변경 없으면 스킵** |
