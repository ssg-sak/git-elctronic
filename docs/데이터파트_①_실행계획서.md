## 0. 한 줄 전략

> **문서 먼저, 코드는 문서와 1:1.** 목데이터로 파이프라인을 완성하고, 실수집은 **입력만 교체**한다.  
> 수집이 끝날 때까지 기다리지 않는다.

```
[정의·매핑] → [목데이터 검증] → [패널·특성·D1/D2] → [EDA·핸드오프] → [실수집 스왑] → [주차·교통 실데이터]
     ↑______________________________ 문서가 각 단계의 완료 증거 ______________________________↑
```

## 4. 문서 작성 규칙 (팀 공통)

### 4.1 새 문서 만들 때

1. 상단 메타 테이블: 역할 · 작성일 · 완료 기준 · 관련 링크  
2. **한 줄 목표** 반드시 포함  
3. 숫자는 CSV/JSON 경로 병기 (`evaluation/results/eda/...`)  
4. "잠정" / "확정" / "mock" 라벨 명시  
5. ② 영역(점수·추천)은 **관찰만** — 정책은 ② 문서

### 4.2 문서 이름 규칙

| 종류 | 패턴 | 예 |
|---|---|---|
| 정본 | `DATA_*.md` · `*_SPEC.md` | 데이터셋_명세 |
| 계획 | `*_PLAN*.md` · `*_실행계획서.md` | 본 문서 |
| 보고 | `*_REPORT*.md` | EDA_REPORT |
| 핸드오프 | `팀공유_*` | ①to② |
| 실험 | `EXP-###_YYYYMMDD_*.md` | 실험노트 |
| 품질 | `docs/data/quality/*.json` | mock_history_report |

### 4.3 스키마·피처 변경 시 (필수 4종 세트)

1. `데이터셋_명세.md`
