# 프론트엔드 에이전트 가이드 (담당 1명)

## 담당 범위

`apps/web/` 디렉터리의 웹 앱 전체. 백엔드 API를 호출해 화면을 구성한다. 추천 점수·위험도 **계산 로직은 백엔드 책임**이므로 프론트엔드에서 재구현하지 않는다. 화면은 백엔드가 내려주는 값을 표시만 한다.

## 구현할 화면 (MVP)

1. **메인 화면**
   - 현재 위치(GPS) 확인, 충전소 검색 버튼
   - 필터: 급속/완속, 충전 규격, 최대 이동시간, 무료 주차 여부
2. **지도 화면**
   - 충전소 마커: 충전 가능 상태별 색상 + 실패 위험도(낮음/보통/높음)별 표시
   - 추천 충전소 강조, 마커에 예상 이동시간 표시
3. **충전소 목록 화면**
   - 추천 순위 순 정렬. 항목당: 사용 가능/전체 충전기 수, 예상 도착시간, 상태 갱신 시각, 실패 위험도
4. **충전소 상세 화면**
   - 충전기별 실시간 상태, 충전 방식·용량, 운영시간, 주차요금
   - 추천 이유 문구(백엔드 제공), 주변 편의시설(카페·공원·편의점 등), 길 안내 연결
5. **충전소 비교 화면 (2~3곳)**
   - 비교표: 거리, 이동시간, 전체/사용 가능 충전기, 상태 갱신, 주차료, 실패 위험도, 최종 추천

## UI 필수 규칙

- **상태 갱신 시각을 항상 노출한다.** 15분 이상 갱신되지 않은 충전소는 "충전기 상태가 N분 전에 갱신되었습니다. 실제 상태와 다를 수 있습니다." 형태의 경고를 표시한다.
- 실패 위험도는 색상 + 텍스트로 함께 표시한다(색상만으로 구분하지 않기 — 접근성).
- 거리보다 **추천 순위(성공 가능성)** 를 기본 정렬로 사용한다.

## 기술 스택

- **Next.js + TypeScript**
- 지도: 카카오맵 또는 네이버 지도 SDK
- API 호출은 `src/services/` 계층으로 분리하고 백엔드 API 명세(`docs/api/` 및 `apps/api/AGENTS.md`)를 따른다
- 화면 기능은 `src/features/` 하위에 배치한다: `map/`(지도), `stations/`(목록·상세), `comparison/`(비교), `nearby-places/`(주변 시설)
- 공용 타입은 `@ev-safecharge/shared-types` 패키지를 사용한다

## 보안 규칙 (중요)

- **외부 API 키(카카오 REST 키, TMAP appKey 등)를 브라우저 코드에 절대 넣지 않는다.** `NEXT_PUBLIC_` 접두사 환경변수로도 노출 금지. 클라이언트에 노출된 키는 타인이 가져가 호출량을 소진할 수 있다.
- 외부 API가 필요한 데이터는 전부 Express 백엔드를 경유해 받는다. (Next.js → 우리 백엔드 → 외부 API)
- 예외적으로 지도 SDK의 JavaScript 키처럼 클라이언트 사용이 전제된 키만 도메인 제한을 걸고 사용한다.

## 협업 인터페이스

- 백엔드 API 응답 스키마가 필요하면 백엔드 담당자와 명세를 먼저 합의하고, 합의 전에는 목(mock) 데이터로 개발한다.
- API 명세 변경 요청은 백엔드 담당자에게 전달한다. 프론트엔드에서 임의로 백엔드 코드를 수정하지 않는다.
