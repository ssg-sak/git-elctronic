---

## 1. 목적

수집 상태를 사람이 매번 수동 확인하면 공백·중복·API 한도 문제를 놓칠 수 있다.
다음 날 첫 수집이 성공할 때 전날 데이터를 자동 점검하고 날짜별 보고서를 남긴다.

자동 점검은 API를 추가 호출하지 않으며 원본 스냅샷을 수정하지 않는다.

---

## 2. 동작

1. `run_loop.py`에서 첫 수집 성공
2. 전날 `daily_checkpoint.json` 존재 여부 확인
3. 없으면 `daily_checkpoint.py` 실행
4. JSON·Markdown·PNG 생성
5. 점검 실패 시 오류만 기록하고 수집 루프는 계속 진행

같은 날짜 보고서가 이미 있으면 다시 만들지 않는다. 수동 재생성은 `--force`로 한다.

```bash
python apps/data-pipeline/evaluation/personal/experiments/SANDBOX_20260717_status_periodic_collection/src/daily_checkpoint.py --date 2026-07-18 --force
```

출력:

```text
apps/data-pipeline/evaluation/results/status_daily/YYYY-MM-DD/
├─ daily_checkpoint.json
├─ daily_checkpoint.md
└─ daily_checkpoint.png
```

---

## 3. 점검 항목

- 일 수집 회차와 활성 시간
- 15분 간격 연속성 및 25분 초과 공백
- API 호출량과 일 한도 사용률
- 결측·잘못된 상태코드
- 원본행과 읽기 단계 중복 제거행 차이
- 누적 고유 충전기와 2/5/10회 이상 반복 관측
- 공백 안전 패널 가용률

가용률은 관측행 평균을 사용하지 않는다. 연속 수집 구간 안에서만 forward-fill하고,
25분을 넘는 공백 뒤에는 이전 상태를 폐기한다.

## 5. 판정

- 일일 점검 파일 3종 생성 성공
- 동일 날짜 중복 생성 방지 확인
- 자동화가 포함된 수집 루프 재시작 후 첫 수집 성공
- 연속 15분·45분 공백 감지 단위 테스트 추가
- evaluation 전체 테스트 **15개 통과**
- 점검 코드 린트 오류 없음

앞으로 수집을 재개하면 전날 보고서가 자동 생성된다.
