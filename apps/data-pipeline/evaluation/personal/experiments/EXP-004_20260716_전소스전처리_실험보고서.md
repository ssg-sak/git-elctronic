## 1. 실험 목적

가까운 충전소가 아니라 **도착했을 때 실제로 쓸 수 있을 가능성**이 높은 충전소를 추천하려면,  
이질적인 공공·mock CSV를 **함부로 한 테이블에 붙이지 않고** 의미를 보존한 채 재사용 가능한 전처리가 필요하다.

본 실험은 다음을 검증한다.

1. 전 소스(실·mock·미확보)를 한 파이프라인에서 다룰 수 있는가  
2. 결측·미수집을 “사용 불가/만차”로 왜곡하지 않는가  
3. 원본을 덮어쓰지 않고 격리 샌드박스에 산출물을 남길 수 있는가

## 5. 해석

1. **추천 점수(가용성)** 를 status만으로 계산하면 97% 이상을 “불가”로 오판한다.  
   → `status_missing` / 관측분 가용률을 **분리 보고**해야 한다.  
2. 교통·주차는 API 장애·IP 제한으로 **mock이 MVP 실험에 정당**하다. `isMock` 유지.  
3. 기상은 **nx=89, ny=90 한 격자**뿐 → “대구 전역 날씨” 표현 금지.  
4. city_tour는 속성 파싱은 가능하나 **좌표 없음** → 공간 조인 전 지오코딩 필수.  
5. 단일 스냅샷으로는 **도착 시 사용 가능성 예측 모델 학습 불가**. 규칙 기반 MVP가 맞다.
