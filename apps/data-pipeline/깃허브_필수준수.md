# GitHub 필수 준수 — 이현석 (AI·데이터 ①)

> **정본(팀 공통):** [`CONTRIBUTING.md`](../../CONTRIBUTING.md) · [`AGENTS.md`](../../AGENTS.md)  
> **개인 작업 가이드:** [`README-이현석.md`](./README-이현석.md)

이 문서는 **내가 매번 지켜야 하는 GitHub·Git 체크리스트**다. 팀 규칙을 DA➀ 역할에 맞게 압축했다.

---

## 1. 브랜치

| 항목 | 규칙 |
|---|---|
| **내 작업 브랜치** | `feature/이현석` |
| **팀 공식 전략** | `main`(배포) ← `dev`(통합) ← `feat/<영역>-<기능>` |
| **절대 금지** | `main`, `dev`에 **직접 push** |

**작업 시작 전 (매번)**

```bash
git checkout main
git pull origin main
git checkout feature/이현석
git merge main          # 충돌은 로컬에서 먼저 해결
```

**푸시·PR**

```bash
git push origin feature/이현석
# GitHub에서 PR 생성 → base는 팀 합의 브랜치 (현재 원격: main / feature/이현석)
```

> 원격에 `dev`가 생기면 PR base를 `dev`로 맞춘다. 팀 채널에서 base 브랜치를 먼저 확인한다.

## 2. 커밋 메시지

형식: **`[영역] 내용`** (한 줄, 명령형)

| 영역 태그 | 내가 쓸 때 |
|---|---|
| `[data]` | processing, evaluation, docs/data, 루프·추출 스크립트 |
| `[docs]` | 팀 공유 문서, 데이터 사전·보고서 |
| `[conflicts]` | 병합 충돌 해결만 할 때 |

**예시**

```
[data] loop1/2/3 경로 통합 및 loop_paths 추가
[data] TourAPI UTF-8 추출기 및 mojibake 복구
[docs] 소통 수집 현황 팀 공유 문서 추가
```

---

## 3. 커밋하면 **안 되는** 것

| 금지 | 이유 |
|---|---|
| `.env`, `.env.local` | API 키·시크릿 |
| `apps/data-pipeline/collection/raw/`, `collection/data/` | 수집 원본 대용량 |
| 대용량 CSV·패널 전체 (`station_feature_panel_*.csv` 등) | git 용량·이력 오염 — `evaluation/results/`는 팀 합의 후만 |
| `scripts/api-tests/*-result.json` | API 테스트 결과 (`.gitignore`) |
| `node_modules/`, `.venv/`, `__pycache__/` | 빌드·가상환경 |
| 남의 담당 디렉터리 **무단 수정** | `apps/api/`, `apps/web/`, `collection/`, `recommendation-core/` |

**키 변경 시:** `.env`는 커밋하지 않고 **`.env.example`만** 갱신한다.

## 4. 내가 수정해도 되는 범위

| ✅ 수정 가능 | ❌ 합의 없이 수정 금지 |
|---|---|
| `apps/data-pipeline/processing/` | `apps/data-pipeline/collection/` |
| `apps/data-pipeline/evaluation/` | `apps/api/`, `apps/web/` |
| `apps/data-pipeline/loop_paths.py` | `packages/recommendation-core/` |
| `docs/data/`, 팀 공유 `docs/팀공유/` | `packages/shared-types/` |
| `evaluation/personal/` SANDBOX·실험 | 남이 쓰는 `docs/data/extracted/` **덮어쓰기** |

**데이터 경계 (커밋 전 한 번 더 확인)**

- SANDBOX status 스냅샷 → `docs/data/loops/loop1/` (공식 루프 경로)
- `docs/data/extracted/` → 1차 추출 정본 (도메인 하위: `charger/`, `tour/`, `parking/` …). SANDBOX가 덮어쓰지 않는다.
- 서버 풀 복사본 → `docs/data/loops/_archive/` (라이브 loop1~3 과 분리)
- 루프 수집 중인 CSV는 **실행 중 파일**과 구분 — 불필요한 대용량 스냅샷은 PR에 넣지 않는다.

## 5. PR 제출 전 체크리스트

PR 템플릿([`.github/pull_request_template.md`](../../.github/pull_request_template.md))을 채운다.

- [ ] 커밋 메시지가 `[영역] 내용` 형식이다
- [ ] `.env`·인증키·토큰이 diff에 없다
- [ ] `git diff`에 담당 밖 디렉터리 변경이 없다
- [ ] 대용량 데이터·개인 실험 산출물이 불필요하게 포함되지 않았다
- [ ] **Breaking Change** — D1/D2 스키마, 피처 컬럼, `docs/data/` 포맷 변경 시 본문에 명시 + ②·백엔드에 사전 알림
- [ ] 관련 `pytest` 또는 스크립트 dry-run을 돌려 봤다
- [ ] `main`을 merge한 뒤 충돌을 해결했다

**PR 본문에 꼭 쓸 것**

- 무엇을 / 왜 바꿨는지 (1~3줄)
- 담당 영역 체크: **AI·데이터 ①**
- 테스트 방법 (예: `pytest apps/data-pipeline/evaluation/tests/ -v`)
- Breaking Change 없으면 **"없음"** 명시

## 6. 병합 충돌 발생 시

1. `git checkout main && git pull origin main`
2. `git checkout feature/이현석 && git merge main`
3. 충돌 파일에서 `<<<<<<<` / `=======` / `>>>>>>>` 제거 — **담당자와 상의** 후 반영
4. 테스트 실행 후:

```bash
git add .
git commit -m "[conflicts] main 병합 충돌 해결"
git push origin feature/이현석
```

## 9. 자주 쓰는 명령 (복붙용)

```bash
# 상태 확인
git status
git diff --stat

# 스테이징 (담당 파일만 골라서)
git add apps/data-pipeline/processing/새파일.py
git add docs/data/변경문서.md

# 커밋
git commit -m "[data] 변경 내용 요약"

# 푸시
git push origin feature/이현석

# PR 생성 (gh CLI)
gh pr create --base main --title "[data] 제목" --body "## Summary\n- ...\n\n## Test plan\n- [ ] pytest"
```

## 10. 하지 말 것 (실수 방지)

| 하지 말 것 | 대신 |
|---|---|
| `git push --force` to `main` / `dev` | 팀 리드에게 요청 |
| `git commit --no-verify` | hook 실패 원인 수정 |
| 전체 `git add .` 후 검토 없이 커밋 | `git diff --cached`로 시크릿·대용량 확인 |
| SANDBOX 실험 전체를 한 PR에 | 기능 단위로 쪼개기 |
| 점수·랭킹·모델 코드를 ① PR에 포함 | ② 영역 — 별도 합의 |
