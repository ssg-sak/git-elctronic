# 백엔드 에이전트 가이드 (담당 1명)

## 담당 범위

`apps/api/` 디렉터리의 API 서버 전체. 데이터 팀이 적재한 가공 데이터를 읽어 프론트엔드에 REST API로 제공한다.  
추천 **점수·위험도·이유·ML 추론**의 설계·구현은 **AI·데이터 ②** (`packages/recommendation-core/` 등)가 담당하고, 백엔드는 이를 호출·연동한다. 산식·입출력 명세 변경 시 ②와 합의한다.

외부 API 연동 코드는 `src/services/` 하위에 도메인별로 배치한다(`charging-station/`, `traffic/`, `weather/`, `parking/`, `places/`, `recommendation/`). 외부 공공 API 직접 수집은 **데이터 수집 담당의 책임**이므로 백엔드에서 중복 구현하지 않는다. 단, 실시간성이 필수인 교통(이동시간) 조회는 백엔드에서 요청 시점에 호출할 수 있다.

## 구현할 API (MVP)

1. `GET /api/stations` — 위치 기반 충전소 검색
   - 파라미터: 위도/경도, 반경(또는 최대 이동시간), 급속/완속, 충전 규격, 무료주차 여부
   - 응답: 추천 점수 순 충전소 목록 (각 항목에 추천 점수, 실패 위험도, 신뢰도 등급, 예상 이동시간 포함)
2. `GET /api/stations/{statId}` — 충전소 상세
   - 충전기별 상태, 운영시간, 주차 정보, 추천 이유 문구, 주변 편의시설
3. `POST /api/stations/compare` — 충전소 2~3곳 비교
   - 비교표 데이터: 거리, 이동시간, 충전기 수, 신뢰도, 주차료, 위험도, 최종 추천
4. `GET /api/stations/{statId}/nearby` — 주변 편의시설 (카페, 음식점, 편의점, 공원, 관광지, 화장실)

## 추천 로직 (규칙 기반, MVP)

가중치와 신뢰도 등급 기준은 루트 `AGENTS.md`의 "핵심 도메인 규칙"을 따른다. 임의 변경 금지.

```
최종 추천 점수 = 충전 가능성(40) + 신뢰도(20) + 이동시간(15) + 대기 위험(15) + 편의성(10)
```

- **충전 가능성**: 사용 가능 충전기 수, 사용 가능 비율, 현재 사용 중 수
- **신뢰도**: 상태 갱신 경과 시간, 정보 누락 여부
- **이동시간**: 교통 반영 예상 이동시간 (직선거리 사용 금지)
- **대기 위험**: 충전기 1대 여부, 고장·점검 비율, 도착 전 선점 가능성
- **편의성**: 주차요금, 운영시간, 주변 시설, 화장실

추천 이유는 사람이 읽을 수 있는 문장으로 생성한다.
예: "B 충전소는 2.1km 떨어져 있지만 전체 충전기 4대 중 3대를 사용할 수 있습니다. 상태 정보도 2분 전에 갱신되었으며 예상 도착시간은 11분입니다."

## 이동시간 계산 (TMAP 경로 API 호출 전략)

TMAP 자동차 경로 안내 API(`.env`의 `TMAP_APP_KEY`)로 실시간 교통 반영 이동시간·도착 예상시각을 얻는다. 호출량 절약을 위해 단계를 나눈다.

1. 사용자 현재 위치 기준 주변 충전소를 **직선거리(하버사인, 서버 계산)** 로 1차 필터링
2. 상위 후보 5곳 내외 선정
3. **최종 후보에만** TMAP 경로 API를 호출해 실제 도로 이동거리, 예상 소요시간, 도착 예상시각을 계산

전 후보에 TMAP을 호출하지 않는다. 응답에서 사용할 필드: 이동거리, 소요시간, 경로 좌표(길 안내용), 통행료.

## 보조 가중치 규칙 (2차 API 연동 후)

추천 점수의 핵심(충전 가능성·신뢰도·이동시간)은 그대로 두고, 아래는 **보조 가중치**로만 반영한다.

- **날씨** (기상청 단기예보): 비·눈·폭염·한파 시 실내 주차장·실내 편의시설 보유 충전소 가점, 먼 충전소 감점. MVP에서는 핵심 요소가 아닌 보조 가중치.
- **주차 혼잡도** (대구 실시간주차혼잡도): 충전기가 사용 가능해도 주차장 잔여 면수가 0이면 진입 실패 위험으로 감점. 잔여 면수가 있으면 추천 유지. 이 API는 등록된 팀 AWS 서버(3.39.251.72)에서만 호출 가능하므로 로컬 개발 시 목 데이터를 사용한다.
- **돌발상황** (대구 돌발 교통정보): 경로 주변 사고 → 교통 위험 경고 표시, 충전소 진입도로 공사 → 감점, 경로상 행사·통제 → 대체 충전소 추천.
- **도로 소통** (대구 교통소통정보): 도착시간 계산은 TMAP이 담당하고, 이 데이터는 혼잡구간 표시와 "추천 이유의 교통 설명"에 사용한다.

## 기술 스택

- **Express (Node.js)**
- DB: PostgreSQL (+ PostGIS로 위치 검색) 권장
- **모든 외부 API 키는 Express 환경변수(`.env`)에만 둔다.** 프론트엔드(Next.js)에는 어떤 외부 API 키도 전달하지 않으며, 외부 API 호출은 전부 이 서버에서 대행한다.

## 협업 인터페이스

- **데이터 팀과**: 가공 데이터 테이블 스키마는 **AI·데이터 ①**과 합의·문서화한다. 백엔드는 읽기 전용.
- **AI·데이터 ②와**: 추천 점수·위험도·이유·추론 I/O·fallback은 ② 산출물을 API에 연동한다. `recommendation-core` 변경 시 상호 확인.
- **프론트엔드와**: API 명세를 먼저 합의·문서화한 후 구현한다. 응답 필드 변경 시 프론트엔드 담당자에게 사전 공지한다.
