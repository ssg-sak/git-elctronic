# 비전공 + 학사 보완 규칙

이 문서 = 지원 전략 보완본. 포폴 **하나**, 서류 말투만 바꿈.

---

## 1. 1~3순위는 동시에 노린다

| | |
|---|---|
| **포폴** | Tier A 세트 **1개** (분석·시각화·리포트) |
| **자소서/면접** | **첫 문장만** DA / BI / 운영·리포팅으로 교체 |
| **지원** | 세 직무 공고를 같은 주에 나눠 넣어도 됨 |

```text
같은 노션 링크
  ├─ 데이터 분석가 공고 → 첫 문장 = 인사이트
  ├─ BI 공고           → 첫 문장 = 대시보드
  └─ 운영·리포팅 공고   → 첫 문장 = as_of·품질 게이트
```

첫 문장 원문: [`03_이력서_면접_한줄.md`](./03_이력서_면접_한줄.md)

---

## 2. 제조·공정·DX (★4) — 선택적으로만

| 상황 | 행동 |
|---|---|
| 공고가 **모니터링·시계열·이상 탐지·대시보드** 중심 | Tier A + DX 한 줄 비유 OK |
| 공고가 **공정/MES/PLC/설비보전** 강함 · 공장 경험 요구 | **억지로 안 넣음** |
| 기본 추천 | 재료는 **서비스·공공·운영** 쪽이 더 자연스러움 |

공장 경험 없이 “공정 DX 전문가”처럼 쓰지 말 것.  
쓸 때는: “상태 시계열 모니터링·공백/이상·시간대 패턴”까지만.

---

## 3. 공공·행정 (★4) — 적극 후보

이 프로젝트와 **의외로 잘 맞음.**

| 재료 | 서류에서 이렇게 |
|---|---|
| EvCharger 등 **공공 API** | 공공·개방데이터 수집·검증 |
| 주차·UTIC **한계 문서화** | 커버리지·권한·품질 한계를 보고 톤으로 정리 |
| 매칭 성공/실패 목록 | 행정·정책 데이터 결합의 현실 |

공공 공고면 Tier A + [`00`](./00_목표직무_포지셔닝.md) 공공 첫 문장.

## 4. 서류 스킬 순서 (비전공·학사)

**앞에:** 분석 · 시각화 · 리포트 / KPI  
**뒤에·짧게:** Python 등 도구  
**거의 안 씀:** 엔지니어링 스택 나열

### 이력서 스킬 칸 예시

```text
데이터 분석 · KPI/리포팅 · 데이터 시각화(Excel, HTML 대시보드, Power BI)
지표 정의(기준시각·신선도·가용률) · 품질 점검(결측·중복·이상)
도구: Python(pandas), Git  |  (필요 시) SQL 기초
```

### 피하기

```text
❌ Python, AWS, Lightsail, ETL, Pipeline, Feature Engineering, Parquet …
   (앞에 이렇게 잔뜩 → DE/비전공 미스매치로 보임)
```

### 프로젝트 bullet 톤

| 좋음 | 나쁨 |
|---|---|
| 시간대별 가용성 분석 → 인사이트 | pandas로 melt/groupby 최적화 |
| 기준시각 있는 KPI 리포트 운영 | Lightsail에서 cron 수집 인프라 |
| 대시보드로 신선도·가용 현황 공유 | parquet 9M행 파이프라인 구축 |

엔지니어링은 면접에서 “어떻게 만들었냐” 물을 때만 도구로 설명.

## 5. 자연스러운 지원 우선순위 (재료 기준)

| 순위 | 직무 | 비고 |
|---:|---|---|
| 동시 | ① 분석가 · ② BI · ③ 운영리포팅 | 포폴 공유 |
| 다음 | ⑤ 공공 · ⑥ 서비스 · ⑦ 기획 | 첫 문장+슬라이드 1 |
| 가려서 | ④ 제조 DX | MES 강공고는 패스 가능 |
| 메인 X | DS · DE · ML | ★★ 이하 |

```
비전공학사 보완 | 1~3 동시 | 공공↑ DX 선택 | 분석·시각화·리포트 우선
```
